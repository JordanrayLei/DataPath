# DataPath 项目理解报告

> 版本：V1.0  
> 产品阶段：作品集 MVP  
> 结论状态：已由项目负责人确认

## 产品简介

DataPath 是面向具备 SQL 基础的数据运营和数据分析师的可信 ChatBI Copilot。它将自然语言问题转换为受约束的 Query DSL，再由后端确定性编译并执行 SQL，最终提供表格、图表、业务解读、指标口径和 Evidence。

产品不以“替用户写一条 SQL”为终点，而是希望降低重复查数成本，并让指标选择、查询执行和结果解释可验证、可追溯、可持续评测。

## 产品目标

- 提升高频标准查数任务的完成效率。
- 减少数据岗位在重复、低复杂度取数上的时间投入。
- 用指标中心统一名称、定义、公式、维度、版本和血缘。
- 辅助发现异常、定位变化并缩小归因范围。
- 通过 Badcase 和黄金问题建立质量迭代闭环。

## 用户画像

首期用户是需要频繁查数且具备一定 SQL 基础的数据运营和数据分析师。他们通常自己编写 SQL，或向其他数据同事发起取数需求；其核心诉求是更快得到可信结果，并保留检查 SQL 和指标口径的能力。

不懂 SQL 的普通业务人员属于产品成熟后的扩展用户，不是当前 MVP 的首要用户。

## 核心流程

```text
创建分析 → 自然语言提问 → 加载会话上下文 → 指标检索与澄清
→ 生成 Query DSL → 校验 → 编译 SQL → 安全执行 → 结果画像
→ Evidence → 业务解读 → Reflection → 表格/图表/口径/SQL
```

当指标不明确、查询不合法或解释缺少证据时，系统采用澄清、拒绝、修订或 Data-only 降级，不继续猜测。

## 功能模块

| 模块 | 当前能力 |
| --- | --- |
| 问数工作台 | 多轮提问、查询链路、表格、图表、解读、Evidence、SQL查看与复制 |
| 指标口径中心 | 指标列表、定义、别名、公式、版本历史、维度、语义模型、血缘查看 |
| 指标管理 | 创建与校验草稿、编辑已发布指标、发布递增不可变版本 |
| 质量运营 | Badcase 提交、状态推进、黄金问题沉淀、回归评测 |
| 测评监控 | 最新测评、用例结果、安全门禁、通过率和耗时趋势 |

## AI 与 Agent 能力

DataPath 当前属于可信 ChatBI Copilot 和 Agentic Workflow，不属于多 Agent 自治系统。Dify 负责 AI 工作流编排，DeepSeek Chat 参与预处理、消歧、DSL草稿和修订；指标口径、SQL编译、数仓执行、Evidence 和 Reflection 由确定性后端控制。

当前没有向量 RAG、MCP、多 Agent 协作或用户长期记忆。Memory 为按工作空间和会话保存指标、维度、筛选及时间条件的结构化上下文。

## 当前边界

- 项目为作品集 MVP，使用模拟电商和广告数据。
- 没有真实用户、客户访谈、试点或业务收益数据。
- 当前不支持用户配置数据源和自由 Join。
- 指标创建、校验和版本发布已形成闭环；多人审核与驳回流程尚未实现。
- 企业组织、SSO、RBAC、行列权限和脱敏属于未来目标。
- 首期只能辅助定位异常、缩小归因范围，不能声称自动完成因果归因。

## 已确定的下一阶段重点

1. 在现有创建与版本发布基础上补齐多人审核和驳回流程。
2. 支持用户接入真实数据源。
3. 提升自然语言问数准确率。
4. 在预定义语义关系和安全校验下支持受控 Join。

## 仍需后续验证

- 首批外部数据源及接入顺序。
- 真实用户的查数效率提升和使用意愿。
- 受控 Join 的配置模式与权限边界。
- 企业版部署、收费和服务等级。
