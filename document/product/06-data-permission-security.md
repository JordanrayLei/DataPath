# DataPath 数据、权限与安全说明

## 1. 数据分类

| 数据类型 | 当前内容 | 存储 |
| --- | --- | --- |
| 指标元数据 | 定义、公式、版本、维度、血缘、Owner | PostgreSQL |
| 查询上下文 | 会话指标、维度、筛选、时间 | PostgreSQL |
| 查询审计 | DSL、SQL、指纹、状态、成本、结果 | PostgreSQL |
| 可信数据 | Profile、Evidence、Reflection | PostgreSQL |
| 质量运营 | Feedback、Badcase、黄金问题 | PostgreSQL |
| 分析数据 | 模拟电商和广告事实数据 | ClickHouse |
| AI编排数据 | Workflow配置和运行上下文 | Dify |

## 2. 当前权限模型

MVP 使用 `public_demo_user` 和固定 `demo` 工作空间，仅用于公开模拟聚合数据。当前已经具备工作空间校验、内部服务令牌、签名执行令牌、查询有效期、只读数仓账号和审计标识，但不构成完整企业权限系统。

## 3. 当前安全控制

- LLM不直接生成并执行任意 SQL。
- Compiler只允许注册的表、字段、指标和维度。
- 查询使用参数绑定、Limit、时间范围和签名令牌。
- 数仓执行账号只读。
- 内部接口使用 Bearer Token。
- Query ID、Trace ID和SQL Fingerprint支持追踪。
- Reflection检测疑似个人信息、凭据、原始SQL泄露和无依据因果表达。
- 不确定时采用 fail-closed。

## 4. 企业化权限目标

建议角色：组织管理员、工作空间管理员、指标管理员、数据分析师、查询用户和审计员。

未来能力包括：SSO、组织和工作空间、RBAC、数据源授权、业务域权限、指标权限、行级策略、列级策略、敏感字段脱敏、审批、操作审计和访问报告。

## 5. 数据源接入要求

- 使用只读凭证和最小权限。
- 密钥进入专用 Secret 管理，不进入Prompt、日志或前端。
- 接入前执行连通性、权限和方言检查。
- Schema发现与字段采样必须可配置和审计。
- 数据源删除后停止新查询，并按策略处理历史快照。
- 不将大规模原始明细发送给LLM。

## 6. Join安全要求

未来只支持语义模型中预定义并审核的 Join关系。每条关系需声明左右模型、键、方向、基数、可用指标、过滤传播和成本等级。Compiler负责选择合法路径，用户文本和LLM不得提供任意物理 Join表达式。

## 7. 合规待办

真实数据试点前需要补齐：隐私政策、数据处理协议、数据保留与删除策略、审计留存周期、敏感数据分级、模型供应商数据条款、跨境评估、备份恢复和安全事件响应。
