# DataPath 产品需求文档 PRD

> 版本：V1.0  
> 产品阶段：MVP 已完成，进入 V1.1 规划  
> 优先级规则：P0 必须、P1 重要、P2 增强

## 1. 背景与机会

数据运营和数据分析师每天需要处理大量重复、必要但低复杂度的 SQL 查数任务。现有方式依赖手写 SQL、复用历史查询或请求其他数据同事，耗费了本应用于洞察、归因和决策支持的时间。

直接 NL2SQL 虽能缩短生成时间，但存在指标口径错误、字段幻觉、危险 SQL、错误 Join 和结果不可追溯等风险。DataPath 通过指标中心、Query DSL、确定性 SQL 编译、Evidence 和 Reflection，在效率与可信之间建立受控链路。

## 2. 产品定位

**一句话定位：** DataPath 是帮助数据运营和数据分析师用自然语言完成可信查数、指标核验和初步异常定位的 ChatBI Copilot。

**核心价值：** 更快得到结果，同时保留专业用户对指标、SQL、数据和证据的检查能力。

## 3. 目标与非目标

### 3.1 MVP 目标

- 支持聚合、趋势、排名和受限比较查询。
- 支持电商经营与广告投放两个演示业务域。
- 返回表格、图表、解读、口径、Evidence 和 SQL查看能力。
- 对歧义、未知指标、非法查询和不可信解释进行门控。
- 建立 Badcase 到黄金问题再到回归评测的闭环。

### 3.2 非目标

- 不自动完成完整因果归因。
- 不允许用户提交任意 SQL 给高权限账号执行。
- 当前不提供自由 Join、数据写回和任意明细导出。
- 当前不提供完整企业账号、权限与指标审批后台。

## 5. 产品范围

### 5.1 问数工作台

输入：自然语言问题、业务域、会话上下文。  
输出：查询状态、指标口径、结果表、图表、业务解读、Evidence、SQL、Query ID。

核心规则：

- 指标必须来自已发布且可见的指标目录。
- 指标歧义时必须澄清，不得静默选择。
- LLM 只能生成 Query DSL 草稿，不直接拥有 SQL 执行权。
- SQL 必须由服务端 Compiler 根据白名单模型和字段生成。
- 数值结论必须引用有效 Evidence。
- 只有描述性证据时，不得输出确定性因果归因。

### 5.2 指标口径中心

当前提供指标浏览与详情、草稿创建、公式与维度校验、递增版本发布和版本历史。V1.1 继续增加多人审核、驳回、废弃和变更影响分析。

指标基础字段包括：指标 ID、名称、别名、业务定义、单位、类型、Owner、公式、聚合方式、时间字段、支持维度、语义模型、血缘、版本和状态。

### 5.3 质量运营

用户可针对指标、数据、图表或解读提交 Badcase。产品运营确认后可将其转为黄金问题，并在模型、Prompt、检索、指标或规则变更后执行回归测评。

### 5.4 测评监控

展示用例通过率、可信门禁、端到端状态、平均耗时和历史趋势。测评结果必须同时记录运行环境、样本量和生成时间。

## 6. 核心状态机

```text
问题提交
├─ PASS → DSL → COMPILE → EXECUTE → PROFILE → REFLECTION → SUCCESS
├─ CLARIFY → 用户选择口径 → 重新进入 DSL
├─ REJECT → 不生成 DSL、不执行查询
├─ BLOCKED → 安全或权限阻断
└─ ERROR → 返回 Request ID / Query ID 和重试提示
```

Reflection 状态：

- `PASS`：展示数据和可信解读。
- `REVISE`：按校验建议修订后再次验证。
- `BLOCK`：仅展示确定性数据、口径和限制。

## 7. 查询规则

- 默认时区为 `Asia/Shanghai`。
- MVP 最大查询跨度为 366 天。
- DSL 支持聚合、趋势、排名和比较意图。
- SQL 使用参数绑定、表字段白名单、Limit 和签名执行令牌。
- 同一 Query ID 的重复执行应返回幂等结果。
- 当前查询结果只读，不允许 DML、DDL 或数据写回。
- V1.1 Join 只能使用语义模型中预先注册、审核通过的关系。

## 8. 结果可信规则

- 每个查询保存指标版本、DSL Hash、SQL Fingerprint 和血缘。
- 每条数值发现至少引用一个 Evidence ID。
- Reflection 检查数字、单位、时间范围、指标版本、敏感信息和因果表达。
- 空结果、数据质量异常或画像失败时必须说明限制。
- AI 服务异常时允许降级为确定性 Evidence 解读或 Data-only。

## 9. 非功能要求

| 维度 | MVP 要求 |
| --- | --- |
| 安全 | 只读数仓账号、服务鉴权、执行令牌、工作空间校验 |
| 可追溯 | Request ID、Trace ID、Query ID、Evidence ID |
| 可靠性 | 失败关闭、幂等执行、确定性解读兜底 |
| 可测试 | 黄金问题、契约测试、Smoke、端到端门禁 |
| 性能 | 记录端到端耗时并持续观察 P95 |
| 可解释 | 展示指标定义、血缘、Evidence 和 SQL |

## 10. MVP 验收基线

- 成功趋势查询可生成 12 个月结果、折线图和 Evidence。
- 排名查询可返回维度贡献和柱状图。
- “毛利”等歧义表达进入澄清，不执行查询。
- 未知指标被拒绝，不生成 DSL。
- 非 demo 工作空间被拦截。
- 内部接口无服务令牌时拒绝访问。
- 用户反馈可进入 Badcase 看板并沉淀为黄金问题。
- 回归评测结果可在测评看板查看。

## 11. 成功标准

作品集阶段以离线质量和系统指标为准，不使用虚构的用户收益：指标识别准确率、DSL正确率、查询执行成功率、Evidence正确率、端到端任务完成率、澄清正确率、危险查询拦截率和 P95响应时间。

## 12. 风险

| 风险 | 影响 | 主要控制 |
| --- | --- | --- |
| 指标误识别 | 返回错误口径 | 指标候选、置信门控、澄清 |
| SQL或Join错误 | 错数或安全风险 | DSL、白名单 Compiler、预定义关系 |
| AI编造结论 | 用户误判 | Evidence、Reflection、降级 |
| 演示集过小 | 测评结果失真 | 扩充黄金问题并注明样本量 |
| 数据源差异 | 接入后查询不兼容 | Connector契约与多方言 Compiler |
