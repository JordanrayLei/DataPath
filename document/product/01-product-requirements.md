# DataPath 产品需求文档

> 版本：V2.0
> 更新日期：2026-07-13
> 当前阶段：Olist 多表作品集 MVP

## 1. 背景

数据运营和数据分析师每天需要完成大量重复的聚合、趋势和排名查询。手写 SQL 或反复向数据同事提需求会挤占分析、归因和业务沟通时间；直接 NL2SQL 又容易产生指标口径错误、字段幻觉、错误 Join 和不可追溯结论。

DataPath 通过指标治理、结构化 DSL、确定性 SQL 编译和 Evidence 约束，在效率与可信之间建立受控链路。

## 2. 产品定位

**DataPath 是帮助数据运营和数据分析师通过自然语言完成可信查数、指标核验和初步异常定位的 ChatBI Copilot。**

核心价值不是“生成 SQL”，而是“在统一口径和安全边界内更快获得可检查的数据答案”。

## 3. 目标与非目标

### 当前目标

- 支持 Olist 数据上的聚合、趋势、排名和连续追问。
- 支持已发布指标及安全事实到维度 Join。
- 返回交互式图表、表格、解读、SQL 和查询追踪信息。
- 对歧义、越界、权限和不可信解读执行门控。
- 提供指标与 Join 关系的草稿、验证和发布能力。
- 通过 360 条黄金集和发布回归管理质量。

### 非目标

- 任意 SQL、自由 Join、DDL/DML 或数据写回。
- 自动完成因果归因、预测或业务动作执行。
- 支付、评价与订单商品之间未经 Aggregate-Before-Join 的多事实分析。
- 企业级账号、SSO、RBAC、多租户和行列权限。
- 将作品集测评结果表述为真实客户收益。

## 6. 查询状态机

```text
SUBMIT
├─ PASS -> DSL -> VALIDATE -> COMPILE -> EXECUTE -> PROFILE -> REFLECT -> SUCCESS
├─ CLARIFY -> 展示候选，等待用户选择
├─ REJECT -> 能力或指标不支持，不执行查询
├─ BLOCKED -> 权限或危险动作阻断
└─ ERROR -> 返回可追踪错误并允许重试
```

`CLARIFY`、`REJECT` 和 `BLOCKED` 必须互斥且有一致定义。当前 7 条发布回归失败均集中在该状态层，是下一迭代 P0。

## 7. 核心规则

- 指标和版本必须为 `PUBLISHED`。
- 完整指标名或最长别名优先于被其包含的短名称。
- 向量和 Reranker 分数用于召回与排序，不直接等同正确概率。
- DSL 只能引用检索返回的指标、可用维度和允许操作。
- SQL 只能由服务端 Compiler 根据白名单字段与已发布 Join Path 生成。
- 所有查询只读、参数化、带 Limit，并保存 DSL Hash、SQL Fingerprint 和血缘。
- 数字解释必须来自执行结果或 Evidence；无证据因果表达必须修订或阻断。
- 同一会话可继承上一轮条件，新会话不继承；显式新条件覆盖旧条件。

## 8. 非功能要求

| 维度 | 当前要求 |
| --- | --- |
| 安全 | Fail-closed、只读账号、服务令牌、签名执行 Token、工作空间校验 |
| 可追溯 | Request ID、Trace ID、Query ID、指标版本、SQL Fingerprint、Evidence ID |
| 正确性 | 独立 SQL Oracle、结果校验和、时间边界、模型血缘 |
| 可测试 | 单元/集成测试、360 条黄金集、80 条发布回归 |
| 降级 | Embedding/Reranker 不可用时回退文本检索；LLM 不可用时使用确定性解读 |
| 性能 | 报告平均延迟、P50、P95 和最大值；当前不承诺生产 SLA |

## 9. 当前验收结果

- 43 项自动测试通过。
- 80 条发布回归通过 73 条，严格通过率 91.25%。
- `core_metric`、`multi_entity`、`multi_turn`、`semantic_robustness`、`data_edge` 均 100%。
- 7 条失败属于状态门禁标签差异，已进入 Bad Case 台账。

## 10. 发布出口

下一版本至少满足：

- 7 条开放回归 Bad Case 全部关闭。
- 新增指标或关系必须有定义、版本、维度、血缘和对应黄金问题。
- 变更后 43 项自动测试和 80 条发布回归无新增失败。
- 文档中的指标数量、Join 状态和评测日期与运行产物一致。
