# DataPath 产品路线图

> 路线图类型：目标导向，不承诺具体发布日期  
> 排序依据：用户价值、可信风险、架构依赖、作品集表达价值

## 1. 当前阶段：MVP

目标：证明自然语言到可信数据答案的完整闭环。

已完成：

- 问数工作台与多轮会话。
- 指标检索、歧义澄清和未知指标拒绝。
- Query DSL、确定性 SQL 编译和 ClickHouse 执行。
- 表格、图表、结果画像、Evidence 和 Reflection。
- 指标口径只读中心。
- 指标草稿、公式与维度校验、递增不可变版本发布和版本历史。
- Badcase、黄金问题、回归评测和测评趋势。
- Dify Workflow 本地端到端联调。

## 2. V1.1：指标治理闭环

目标：让指标从“预置配置”升级为可运营的产品资产。

| Epic | 核心范围 | 成功出口 |
| --- | --- | --- |
| 指标草稿 | 新建、编辑、校验、保存草稿 | 已完成 |
| 版本发布 | 发布递增不可变版本并进入问数 | 已完成 |
| 审核治理 | 提交、审核、驳回、废弃 | 只有审核通过版本进入问数 |
| 版本增强 | 差异对比、回滚指引 | 查询快照可追溯到版本 |
| 影响分析 | 关联黄金问题、历史查询和血缘 | 变更前可见影响范围 |

## 3. V1.2：真实数据源接入

目标：从内置演示数仓扩展到用户自有数据环境。

建议顺序：PostgreSQL / MySQL → ClickHouse外部实例 → 主流云数仓。

核心范围：连接配置、连通性测试、只读凭证、Schema发现、语义模型映射、字段采样、数据预览、方言适配、连接审计和密钥管理。

成功出口：用户可在不修改核心问数链路的情况下接入一个新数据源，并通过标准黄金集验证查询正确性。

## 4. V1.3：准确率与受控 Join

目标：提升真实问法覆盖，并支持安全的跨表分析。

核心范围：

- 扩充真实业务表达和歧义样本。
- 评测指标拆分到检索、DSL、Compiler和端到端层。
- 建立 Prompt版本、规则版本和模型版本对比。
- 在语义模型中配置 Join关系、基数、方向和适用指标。
- Join路径只能由 Compiler 从已审核关系中选择。
- 增加高成本查询预估、确认和阻断。

## 5. 企业化目标

进入真实试点后再启动：组织与工作空间、SSO、RBAC、行列权限、敏感字段脱敏、操作审计、限流、监控告警、备份恢复、私有化部署和服务等级。

## 6. 暂不优先

- 多 Agent 自治分析。
- MCP 接入。
- 用户长期画像记忆。
- 自动数据写回和业务动作执行。
- 在缺少业务上下文时输出自动因果归因。

这些方向只有在真实用户任务证明其价值且安全边界明确后再进入路线图。
