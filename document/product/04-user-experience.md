# DataPath 用户体验与页面说明

> 更新日期：2026-07-13

## 1. 体验原则

- 专业用户优先：结果可检查，指标、SQL、血缘和查询追踪不能成为黑盒。
- 结果优先：默认突出数据与业务结论，技术细节按需展开。
- 不确定性可见：澄清、拒绝、阻断、降级和数据限制必须明确。
- 上下文透明：用户应知道系统继承了哪些指标、维度和时间。
- 运营闭环：失败结果可以直接进入 Bad Case 和回归流程。

## 2. 信息架构

| 导航 | 核心任务 |
| --- | --- |
| 01 问数工作台 | 创建会话、自然语言提问、连续追问、查看交互结果 |
| 02 指标口径 | 浏览定义、公式、别名、维度、版本、模型与血缘 |
| 03 质量运营 | 查看 Bad Case、推进状态、沉淀黄金问题 |
| 04 测评监控 | 查看入口测评、通过率、失败门禁和历史趋势 |
| 05 指标管理 | 创建草稿、预览公式、校验并发布版本 |
| 06 Join 治理 | 管理模型、关系草稿、候选检测和发布 |

## 3. 问数工作台

### 空状态

提供三个当前 Olist 能力示例：成交总额趋势、客户州买家排名和品类客单价。点击后将完整问题写入输入框，不自动执行。

### 会话

- 左侧展示当前浏览器会话列表。
- 同一会话保存多轮消息和结构化查询上下文。
- 点击“新建分析”创建无继承条件的新会话。
- 开发阶段不将旧浏览器历史视为正式持久化能力。

### 运行与结果

提交后展示用户问题和运行状态。成功结果包括：

- 可信状态、指标、时间范围和 Query ID。
- KPI、趋势或排名图表。
- 数据表和完整返回状态。
- 查看明细、导出、SQL 查看与复制。
- Evidence 数量和 Reflection 状态。

右侧不再展示独立“证据与口径”面板；口径详情统一进入指标口径中心，结果卡保留可信状态与追踪信息。

### 澄清、拒绝和错误

- `CLARIFY`：展示候选指标，用户选择后继续。
- `REJECT`：说明当前指标或能力不支持，不编译 SQL。
- `BLOCKED`：说明权限或危险动作被阻断。
- `ERROR`：展示可理解的错误和追踪标识，不直接暴露内部堆栈或非 JSON 服务响应。

## 4. 指标口径

列表只显示指标和版本均为 `PUBLISHED` 的指标。当前共 12 个，可查看名称、定义、公式、单位、Owner、别名、维度、语义模型、物理表、字段血缘和版本历史。

该页面是治理结果的阅读入口，不是数据库字段浏览器；字段或表不会自动变成业务指标。

## 5. 指标管理

支持新建或编辑指标草稿、选择语义模型与字段、配置公式、选择维度、执行校验并发布下一不可变版本。

当前没有提交审核、驳回、废弃和影响分析。页面上的发布属于单人演示工作流。

## 6. Join 治理

支持查看语义模型和已发布关系、创建关系草稿、检测基数/覆盖率/Fanout、扫描关系候选并发布。

当前展示以列表和编辑器为主，发布/未发布状态的图可视化区分不足。Graph 可视化与元数据定时同步已进入后续计划。

## 7. 质量运营与测评

质量运营承载用户反馈、黄金问题和回归候选；测评监控承载较小的产品入口 Smoke 与历史趋势。360 条 Olist 黄金集和发布回归由脚本运行，当前详细报告通过文档链接查看。

## 8. 响应式与可用性要求

- 不允许按钮文字、表格和结果卡在桌面或移动端重叠。
- 图表和表格切换不改变主要布局尺寸。
- 操作按钮使用明确命令或熟悉图标，并提供可访问名称。
- 长指标名、错误信息和血缘字段必须换行或截断，不溢出容器。
- 每次前端调整后至少验证空状态、成功、澄清、错误和窄屏布局。
