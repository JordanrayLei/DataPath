# DataPath 产品指标与评测方案

> 版本：V2.0
> 更新日期：2026-07-13

## 1. 评测原则

- 作品集阶段以离线任务质量为主，不虚构活跃用户、节省工时或商业收益。
- 检索、状态门禁、DSL、Join、执行、结果和 Reflection 分层判断。
- 成功用例必须有独立 ClickHouse SQL Oracle，不以系统自身 SQL 验证自身。
- 开发集可用于诊断，回归集用于发布门禁，盲测集不得进入 Prompt、别名或语义样本。
- 每次报告必须记录代码/数据/指标/模型版本、样本量、时间和延迟。

## 2. 北极星指标

**可信任务完成率：** 用户问题在正确指标、正确维度、正确时间、正确模型血缘和正确结果下完成，并通过 Reflection；澄清、拒绝和阻断也必须符合预期状态。

## 3. 黄金集

当前 Olist 黄金集共 360 条：

| 类别 | 数量 |
| --- | ---: |
| 核心指标查询 | 100 |
| 治理多实体查询 | 100 |
| 语义鲁棒性 | 30 |
| 歧义澄清 | 20 |
| 多轮上下文 | 40 |
| 能力边界与安全 | 35 |
| 权限阻断 | 15 |
| 数据边界 | 20 |

数据拆分：开发集 220、发布回归集 80、逻辑盲测集 60。公开仓库中的盲测只能形成流程隔离，不能替代私有外部盲测。

## 4. 判定维度

| 层级 | 主要指标 |
| --- | --- |
| Retrieval | Top1、Recall@K、MRR、候选间距、误拒绝率 |
| Status Gate | CLARIFY/REJECT/BLOCKED Precision、Recall 和混淆矩阵 |
| DSL | 指标、维度、时间、意图和 Query Mode Structural Match |
| Join | 预期模型血缘、安全路径、Fanout 门禁 |
| Execution | 行数、结果校验和、总值、Top 值、时间边界 |
| Answer | Evidence 覆盖、数字一致性、单位、Faithfulness |
| Safety | 非授权工作空间、危险动作、SQL 泄露和写操作拦截 |
| Performance | 平均、P50、P95、最大延迟和外部模型耗时 |

## 5. 当前结果

### 自动测试

- 43 项 Python 自动测试通过。
- 覆盖前端入口、指标管理、Join Graph、向量门禁、多表执行、上下文、黄金集和时间边界。

### 产品入口 Smoke

- 30 个产品用例 + 6 个可信门禁，36/36 通过。
- 该集合用于快速回归，不代表完整质量。

### Olist 发布回归

- 评测范围：80 条 regression。
- 严格通过：73/80，91.25%。
- 平均延迟 291.69 ms，P95 2246.33 ms。
- 核心指标、多实体、多轮、语义鲁棒性、权限和数据边界为 100%。
- 7 条失败集中在状态门禁：3 条歧义问题期望澄清但实际拒绝，4 条危险动作的 BLOCKED/REJECT/CLARIFY 标记不一致。

详见 [最新回归报告](../../reports/olist-expanded-metrics-regression.md)。

## 6. 发布门禁

当前版本发布前必须满足：

- 自动测试无失败。
- 核心指标、多实体、执行结果和权限用例不得回归。
- 新指标必须有口径、版本、维度、血缘和黄金用例。
- 新 Join 必须通过基数、覆盖率和 Fanout 检测。
- 结果数值、单位或时间边界失败一律阻断发布。
- 状态策略变化必须更新黄金标签和产品定义，不能只改系统迎合报告。

## 7. Bad Case 闭环

```text
线上/评测失败
-> 自动聚类与责任层定位
-> 人工确认期望行为
-> 修指标/检索/门禁/DSL/Compiler
-> 加入开发或回归资产
-> 复跑并关闭
```

当前开放台账见 [Olist Bad Case](../../data/evaluation/badcases/olist-golden-open-badcases.md)。

## 8. 后续补强

- 保留私有盲测集，避免公开问题泄漏。
- 建立按指标族、问法难度和业务域的动态阈值校准。
- 增加 Join Relation ID 的直接断言和多轮逐轮结果 Oracle。
- 关联 Git Commit、指标版本、Embedding、Reranker、Prompt 和数据快照。
- 获得真实用户任务后增加完成时间、人工修正率和采用率。
