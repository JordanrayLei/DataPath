# DataPath 产品指标与评测方案

## 1. 评测原则

当前没有真实用户数据，作品集阶段以离线黄金集和系统运行数据评价产品。任何准确率必须同时披露样本量、业务域、运行环境、模型、规则版本和生成时间。

## 2. 北极星指标

**可信问数任务完成率**：用户问题在无需人工改写 SQL 的情况下，返回正确指标、正确查询结果和通过可信门禁的答案所占比例。

当前只能使用黄金问题近似计算；进入真实试点后再加入用户确认与任务完成信号。

## 3. 核心质量指标

| 指标 | 定义 |
| --- | --- |
| 指标识别准确率 | 正确选择指标及版本的问题数 / 可判定问题数 |
| DSL正确率 | 指标、维度、时间、筛选、排序和意图均正确的问题数 / 总问题数 |
| 查询执行成功率 | 成功编译并执行的合法查询数 / 应执行查询数 |
| Evidence正确率 | 数值、单位、时间和行引用均匹配的Evidence数 / Evidence总数 |
| 端到端任务完成率 | 最终状态与期望一致且结果满足断言的问题数 / 总问题数 |
| 澄清正确率 | 应澄清且正确澄清的问题数 / 应澄清问题数 |
| 非法查询拦截率 | 被正确拒绝或阻断的危险请求数 / 危险请求总数 |
| P95响应时间 | 95%端到端请求完成所需时间上界 |

## 4. 产品运营指标

真实试点后采集：提问用户数、每用户查询数、重复使用率、澄清后继续率、SQL复制率、Badcase率、结果认可率、人工修正率、平均节省时间和用户满意度。

这些指标当前仅为规划，不得出现在“已取得成果”中。

## 5. 黄金问题分层

| 类型 | 示例 | 预期状态 |
| --- | --- | --- |
| 标准聚合 | 最近30天 GMV | SUCCESS |
| 趋势 | 最近一年每月 GMV | SUCCESS |
| 排名 | 各地区 GMV 排名 | SUCCESS |
| 比较 | 本周与上周支付订单量 | SUCCESS |
| 歧义 | 看看毛利 | CLARIFY |

| 多轮 | 再按地区拆分 | SUCCESS且继承正确 |

## 6. 发布门禁

每次修改模型、Prompt、指标、检索规则、DSL Schema、Compiler或语义模型后必须运行回归。建议在黄金集扩大后设定正式阈值；当前小样本阶段不人为制定虚假高精度承诺。

必须保持的硬门禁：

- 未知指标不生成可执行查询。
- 非法或越权请求不执行。
- SQL不由 LLM 直接执行。
- 数值结论不存在未知 Evidence。
- 敏感数据和无依据因果结论被阻断或降级。

## 7. 当前测评解读

最新本地报告记录 36/36 检查通过，包括 30 条 Olist 业务用例和 6 个安全、上下文及运营门禁。结果证明当前本地链路及指定数据快照可运行，不能等同于真实用户环境下的泛化准确率。完整结论见《DataPath Olist多表业务测评报告》。

## 8. 评测版本记录

每次报告至少保存：报告 ID、时间、代码版本、模型、Prompt版本、指标目录版本、数据快照、用例数、通过率、失败明细、平均与P95耗时。
