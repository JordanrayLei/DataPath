# DataPath Embedding向量索引实施报告

> 版本：V1.0  
> 日期：2026-07-12  
> 状态：已实施，待持续扩充未见问法

## 1. 实施范围

- Embedding Provider：阿里云百炼 `text-embedding-v3`。
- 向量维度：1024。
- 向量存储：PostgreSQL 16 + pgvector 0.8.4。
- 索引类型：HNSW + cosine distance。
- 指标语义文档：指标名称、业务定义、别名、正向样例、反向样例。
- 能力边界文档：按业务域独立维护的 `OUT_OF_SCOPE` 样例及原因。

## 2. 在线检索策略

1. 优先执行精确名称、别名和本地文本检索。
2. BM25对指标名称、定义、别名和典型问法执行稀疏召回。
3. 本地最高分低于0.70时调用Embedding扩召回。
4. 指标支持证据低于0.70时不采纳向量候选。
5. 能力边界相似度达到0.64，且与最高支持证据分差不超过0.06时拒绝。
6. 通过边界门控后，使用`qwen3-rerank`对Top候选进行请求内相对精排。
7. 融合BM25、向量和Reranker信号，再执行候选分差和置信度门禁。
8. Embedding或Reranker调用异常时自动降级，不直接放行查询。

阈值是当前数据集上的基线配置，不是永久常量。后续每次调整必须绑定独立盲测报告，并保留旧版本结果用于对比。

## 3. Bad Case闭环

| Bad Case类型 | 处理动作 | 是否改代码 |
| --- | --- | --- |
| 新同义问法未命中 | 增加正例或别名并重建索引 | 否 |
| 相邻指标混淆 | 增加指标反例并重建索引 | 否 |
| 数据字段缺失仍被猜测 | 增加业务域能力边界样例 | 否 |
| 大范围误召回 | 调整检索/门控版本并重新盲测 | 是 |
| Embedding服务失败 | 监控告警并使用本地检索降级 | 否 |

## 4. 已知限制

- 当前索引规模小，HNSW的性能优势尚未被充分体现。
- 在线弱匹配需要外部Embedding调用，尾延迟高于精确匹配。
- 首批能力边界样例来自现有评测集归因，仍需用全新AI问题集和未来真实日志验证泛化。
- 当前不支持多表Join、预测、用户生命周期和缺失字段推导。

## 5. 上线前门槛

- 主回归集与AI盲测无新增失败。
- 域外问题不得从 `REJECT` 回退为 `CLARIFY` 或 `SUCCESS`。
- Embedding故障时核心精确查询保持可用。
- 密钥仅通过环境变量注入，日志和报告不得记录密钥。
- 建立调用量、P95延迟、错误率、向量命中率和澄清率监控。
