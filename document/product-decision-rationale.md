# DataPath｜产品决策说明

> 更新日期：2026-07-13
> 用途：产品答辩、面试追问和架构取舍说明

## 决策摘要

| 决策 | 当前选择 | 不选择 | 原因 |
| --- | --- | --- | --- |
| 用户入口 | 独立前端 + FastAPI BFF | 直接暴露 Dify | 需要稳定交互、治理与可信结果 |
| AI 取数 | 指标检索 + DSL + Compiler | LLM 直接 SQL | 控制口径、安全和回归 |
| 多表 | Semantic Join Graph + Planner | 模型自由 Join | 控制基数和 Fanout |
| 检索 | 规则 + BM25 + Embedding + Reranker | 纯向量 Top1 | 相似度不是正确概率 |
| 输出可信 | Evidence + Reflection | 只返回自然语言 | 数字必须可追溯 |
| 质量运营 | Bad Case -> 黄金集 -> 回归 | 一次性 Demo | 让质量可持续迭代 |
| 权限 | demo 身份 + 服务端门禁 | 伪装完整企业 RBAC | 诚实聚焦核心链路 |

## 1. 为什么不直接 NL2SQL

直接 NL2SQL 的主要风险不是 SQL 语法，而是指标口径、字段权限、错误 Join 和结果不可解释。DataPath 让 AI 输出受约束意图，服务端根据已发布指标和字段编译 SQL。

代价是需要建设指标中心、DSL 和 Compiler；收益是可校验、可审计、可回归和可迁移到更多执行引擎。

## 2. 为什么指标中心仍是核心

指标中心不是展示页，而是在线检索、DSL 校验、SQL 编译和结果解释的共同事实源。当前 12 个指标包含名称、别名、定义、公式、单位、维度、模型、血缘和版本。

数据库新增字段不会自动成为指标。业务指标需要定义、验证和发布，否则模型只能看到技术字段，无法保证业务口径。

## 3. 为什么需要 Semantic Join Graph

真实分析经常跨表，但自由 Join 会产生错误路径和 Fanout。DataPath 把关系、基数、方向、键和风险策略显式建模，Planner 只使用已发布的 `many_to_one + safe` 关系。

支付与评价关系虽然存在，但保持 `STAGED`，因为多事实查询必须先实现 Aggregate-Before-Join。这种“知道关系但不立即开放”是产品安全选择，不是功能遗漏。

## 4. 为什么不是纯向量 RAG

指标名具有精确业务含义。“运费”与“运费率”语义接近，但不能互换。系统先执行完整名称和最长别名匹配，再用 BM25、Embedding 和 Reranker补充口语召回。

向量分数只表达相似度，不是正确概率；最终还要经过候选间距、负例边界、发布和权限门禁。

## 5. 为什么设计 Query DSL

DSL 是自然语言与 SQL 之间的稳定契约，表达指标、版本、维度、时间、筛选、排序、Limit 和 Query Mode。它让前端、Dify、Validator、Compiler 和评测围绕同一结构协作。

Olist 多表链路使用 DSL 2.0 扩展表达 `multi_entity`；历史 JSON Schema 仍保留 DSL 1.0 基础契约，后续应补独立 2.0 Schema。

## 6. 为什么需要 Evidence 和 Reflection

SQL 正确不代表解读正确。Evidence 将指标版本、值、单位、时间、维度和行引用绑定到结论；Reflection 检查数字、单位、版本、敏感信息和因果表达。

当 AI 服务不可用或解释不可信时，系统降级到确定性 Evidence 解读或 Data-only，而不是扩大模型自由度。

## 7. 为什么 Dify 不是主入口

Dify 适合编排 LLM 和 HTTP 工具，但业务用户需要会话、交互图表、口径治理、质量运营和稳定错误处理。当前 FastAPI BFF 可独立完成主链，Dify 作为可选交付资产保留。

这也避免 Dify 插件或模型异常成为产品不可用的单点。

## 8. 为什么做黄金集而不只看 Demo

AI 产品改一个别名、阈值或 Prompt 都可能引发回归。DataPath 构建 360 条分层黄金集，并为成功用例使用独立 SQL Oracle。

当前 80 条发布回归通过 73 条。没有隐藏剩余 7 条，而是将其定位到状态门禁层，作为下一迭代 P0。这比只展示成功截图更能说明产品质量治理能力。

## 9. 为什么权限暂时简化

当前作品集目标是验证可信问数与多表治理，因此只实现 demo 工作空间、公开演示身份、内部 service token、签名执行 Token 和只读数仓。

这不等于企业权限。真实试点前必须补齐 SSO、RBAC、行列策略、ACL-aware Retrieval、审计和密钥管理。

## 10. 当前最重要的产品判断

DataPath 的核心不是让 AI 更自由，而是把 AI 的语言能力放进指标、Join、DSL、权限、执行和证据约束中。任何新增智能能力都必须同时回答：它如何验证、如何拒绝、如何降级、如何审计、如何进入回归。
