# DataPath 产品决策记录

这份文档记录项目过程中的几个关键选择。它们并不都是“最佳实践”，而是结合企业数据风险、项目阶段和有限开发资源之后的取舍。

## 决策 1：不使用自由 Text-to-SQL 作为生产执行入口

### 问题

自由 Text-to-SQL 同时把以下决策交给概率模型：

- 指标；
- 表；
- Join；
- 聚合；
- 时间；
- 权限；
- SQL 安全。

SQL 可以执行不代表业务口径正确。

### 备选方案

1. 大模型直接生成 SQL；
2. 大模型生成 SQL，再做关键词检查；
3. 大模型生成受约束 DSL，后端确定性编译；
4. 只提供预制报表，不支持问数。

### 决策

采用受治理 DSL 和确定性 SQL 编译。

### 代价

- 查询开放性降低；
- 上线前需要治理指标和关系；
- 暂时无法支持任意探索。

### 收益

- 执行前可以校验；
- 权限不依赖 Prompt；
- SQL 方言与自然语言解耦；
- DSL 可以版本化和回归；
- 错误更容易归因。

## 决策 2：AI 只扩展语言，不自动发布业务事实

### 问题

大模型可以理解通用语言，但不知道企业内部：

- “收入”采用哪个口径；
- 退款是否扣除；
- 订单按创建还是支付时间统计；
- 哪条 Join 是业务有效关系。

### 决策

业务人员确认模型、粒度、指标、公式、单位、Join 和权限；AI 生成别名、典型问法和反例草稿。

AI 草稿必须人工确认后才能应用。

### 取舍

牺牲部分自动化，换取业务事实的责任边界和可审计性。

## 决策 3：使用混合召回，而不是只依赖向量

### 问题

只使用向量召回时：

- 专有名词可能被语义相近表达替代；
- 短指标名称区分不足；
- 相似指标容易混淆；
- 时间和报告用途会干扰检索。

### 决策

组合：

- 完整名称；
- 最长别名；
- 中文词法；
- BM25；
- 正反例；
- 本地 BGE 向量；
- 可选 Reranker。

精确名称和最长别名具有确定性优先级。

## 决策 4：大模型只能裁决有限候选

### 问题

即使检索已经提供候选，大模型仍可能：

- 发明候选；
- 选择旧版本；
- 在低置信度情况下强行回答；
- 忽略权限和资产状态。

### 决策

模型只能选择签名候选集中的指标，或者输出澄清/拒绝。后端检查候选、版本、签名和置信度。

### 收益

模型能力被限制在最适合它的语言消歧环节。

## 决策 5：失败关闭，而不是最大化回答率

### 问题

ChatBI 如果以回答率为主要目标，会倾向于对歧义、超范围和权限不足问题给出猜测答案。

### 决策

定义四类终态：

- `SUCCESS`
- `CLARIFY`
- `REJECT`
- `BLOCKED`

### 产品原则

- 歧义时澄清；
- 超范围时拒绝；
- 权限和安全不满足时阻断；
- 只有完整门禁通过才成功。

## 决策 6：Join 必须成为治理资产

### 问题

多表分析中，字段同名或数据库存在外键不代表业务关系一定成立。错误基数和 Fanout 会产生看似合理的错误数字。

### 决策

Join 必须记录：

- 两端实体；
- 关联键；
- 基数；
- Join 类型；
- Fanout；
- 验证快照；
- 发布状态；
- 版本。

多对多默认阻断；跨事实指标强制先聚合后连接。

## 决策 7：Schema 变化后保持阻断，不能自动恢复

### 问题

字段恢复或类型重新兼容，不代表原业务口径仍然成立。

### 决策

Schema 变化影响指标后，即使物理字段恢复，也需要负责人复核并重新发布模型、关系和指标。

### 收益

避免系统在结构恢复后自动放行已经失效的业务契约。

## 决策 8：用户反馈必须转化为人工 Golden

### 问题

点赞和点踩没有定义正确答案。直接把原系统结果作为 Golden 会产生自我验证。

### 决策

工作人员必须主动确认：

- 正确终态；
- 正确指标；
- 正确查询形态；
- 正确结果或 Oracle；
- 允许误差。

修复发布前必须回归关联 Golden。

## 决策 9：结构问题不能通过语义关键词修复

### 问题

为了快速让某个问题通过，团队可能不断增加别名和 Prompt，但真正错误可能来自公式、Join、Schema 或权限。

### 决策

Bad Case 自助闭环只允许修改不改变计算结果的语义内容。结构问题必须回到对应治理模块。

### 收益

避免局部调优掩盖系统性数据错误。

## 决策 10：先做可信链路，不重建完整 BI

### 问题

完整 BI 包含 ETL、仪表板、大屏、填报、移动端、缓存和大量连接器。正面复制会分散有限资源。

### 决策

优先完成：

- 语义治理；
- 查询安全；
- Evidence；
- Reflection；
- Schema 影响；
- Golden 回归。

### 后续方向

将 DataPath 发展为可接入已有 BI、指标平台和企业 Agent 的可信语义与质量控制层。
