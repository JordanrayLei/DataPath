# DataPath 权限设计

## 1. 设计目标

| 目标 | 产品要求 |
| --- | --- |
| 最小权限 | 用户只获得完成当前职责所需的能力和数据范围 |
| 默认拒绝 | 身份无效、权限缺失、范围不明或上下文不一致时不执行查询 |
| 职责分离 | 管理指标不等于可以查看业务明细，处理质量问题也不自动获得全量数据权限 |
| 服务端生效 | 不依赖前端隐藏按钮，也不依赖大模型遵守提示词 |
| 全链路一致 | 召回、编译、执行、Evidence 和多轮上下文使用同一权限范围 |
| 可追溯 | 查询结果能够说明使用了哪个角色、范围和权限策略版本 |
| 可演进 | 支持从当前固定角色扩展到企业组织、业务域和自定义数据策略 |

## 2. 权限模型

DataPath 采用“角色权限 + 资源范围 + 数据范围”的组合模型。

### 2.1 权限判定公式

```text
是否允许
= 身份有效
∩ 角色允许该动作
∩ 资源位于授权范围
∩ 数据满足行级策略
∩ 当前上下文状态合法
```

一次权限请求由四类信息组成：

| 要素 | 内容 | 示例 |
| --- | --- | --- |
| 主体 Subject | 操作者、角色、所属租户 | `production_tenant_1`、租户 1 分析师 |
| 动作 Action | 查看、查询、创建、编辑、发布、处置 | 查询指标、发布指标、确认 Golden |
| 资源 Resource | 工作空间、业务域、指标、模型、问题单 | `production_benchmark`、订单量 |
| 上下文 Context | 环境、会话、治理状态、策略版本 | Development、指标已发布、策略 v1 |

### 2.2 四层控制

| 控制层 | 解决的问题 | 实现位置 |
| --- | --- | --- |
| 身份认证 | 当前操作者是谁，凭证是否有效 | 签名身份令牌、服务令牌 |
| 功能权限 | 是否允许执行查询、发布、治理等动作 | 服务端接口和领域服务 |
| 资源权限 | 可以访问哪些工作空间、业务域和指标 | 角色与业务域授权 |
| 数据权限 | 查询结果可以包含哪些租户或组织的数据 | 查询编译阶段注入行级过滤条件 |

## 3. 角色设计

角色按职责定义，不按照页面定义。一个用户可以在不同工作空间拥有不同角色。

| 角色 | 核心职责 | 默认数据范围 | 当前状态 |
| --- | --- | --- | --- |
| 业务查看者 | 使用已发布指标完成日常问数 | 已授权业务域 | 已实现 |
| 业务分析师 | 进行全国范围的分析与追问 | 全国 | 已实现 |
| 租户分析师 | 分析所属租户数据 | 指定租户 | 已实现 |
| 指标管理员 | 定义、审核和发布指标及语义资产 | 默认无业务数据查询权 | 已实现基础隔离 |
| 质量运营 | 受理 Bad Case、确认归因、维护 Golden | 与问题单授权范围一致 | 规划 |
| 数据平台管理员 | 管理数据源、业务域、模型和 Schema 影响 | 管理范围内的元数据 | 规划 |
| 权限管理员 | 分配角色、数据范围并审计权限变化 | 不因管理权限自动获得业务数据 | 规划 |
| 系统服务身份 | 执行内部编译、评测和后台任务 | 由服务用途限定 | 已实现服务令牌 |

指标管理员默认不能查询业务数据，是职责分离的关键：维护指标口径需要看到定义、血缘和测试状态，但不应因此自动获得经营明细。

## 4. 资源层级

权限继承遵循以下层级：

```text
工作空间
└── 业务域
    ├── 数据模型
    │   ├── 字段与维度
    │   └── Join 关系
    ├── 指标与指标版本
    │   └── 语义资产与预热草稿
    ├── 查询与 Evidence
    ├── Bad Case 与 Golden
    └── 测评报告
```

上层授权不代表自动获得全部下层动作。例如，拥有业务域查看权可以浏览已发布指标，但不能编辑或发布指标；拥有指标管理权也不自动继承业务数据查询权。

## 6. 数据范围设计

### 6.1 范围类型

| 数据范围 | 适用对象 | 查询表现 |
| --- | --- | --- |
| 全国 | 总部业务分析师 | 可返回授权业务域内的全国数据 |
| 指定租户 | 区域、门店或租户分析师 | 编译 SQL 时自动加入租户过滤条件 |
| 无业务数据 | 指标、权限等治理角色 | 可管理元数据，但问数请求被拒绝 |
| 自定义组织范围 | 后续企业组织接入 | 按组织树、区域或数据标签组合过滤 |

### 6.2 行级权限

租户范围不由大模型生成，也不从用户问题中提取。系统在 Query DSL 通过治理校验后，由查询编译器注入参数化的租户过滤条件。

例如，租户 1 分析师查询“本月订单金额”时，业务问题和指标定义保持不变，编译结果额外绑定：

```text
acl_tenant_id_0 = 1
```

这样可以避免用户通过提示词删除过滤条件，也可以防止模型忘记添加条件。

### 6.3 多轮会话

多轮上下文只能由同一操作者继续使用。用户切换身份或数据范围后，不能继承上一身份的指标、筛选条件和查询结果；系统需要重新完成权限预检。

## 7. 关键操作的权限规则

### 7.1 自然语言问数

一次查询按以下顺序完成校验：

1. 工作空间与请求上下文一致；
2. 身份令牌签名有效且未过期；
3. 角色具备业务数据查询权限；
4. 目标业务域位于授权范围；
5. 指标、维度和 Join 均处于可用治理状态；
6. 查询不包含危险写入意图；
7. 编译器注入行级权限并生成带时效的执行令牌；
8. 执行时再次校验操作者和工作空间；
9. Evidence 记录角色、数据范围和策略指纹。

任一步失败，查询均不进入下一阶段，也不会产生可执行 SQL。

### 7.2 指标发布与 AI 语义预热

| 操作 | 权限要求 | 附加门禁 |
| --- | --- | --- |
| 创建指标草稿 | 指标管理员 + 业务域管理范围 | 指标名称、公式和血缘完整 |
| 生成预热草稿 | 指标草稿编辑权 | 仅基于已确认定义生成 |
| 审核预热内容 | 指标管理员或指定审核人 | 人工确认后才能应用 |
| 发布指标 | 指标发布权 | 治理校验和回归测评通过 |
| 下线指标 | 指标发布权 | 提示依赖与影响范围 |

AI 生成能力不拥有发布权限。模型只能生成草稿，最终生效必须经过具备权限的人员确认。

### 7.3 Schema 影响管理

| 阶段 | 允许角色 | 权限规则 |
| --- | --- | --- |
| 扫描并发现变化 | 系统服务身份 | 仅访问已配置数据源的元数据 |
| 查看影响范围 | 数据平台管理员、受影响资产负责人 | 仅查看管理范围内的模型和指标 |
| 标记影响和阻断 | 系统服务身份 | 按确定性依赖关系自动执行 |
| 修复模型或字段映射 | 数据平台管理员 | 记录修改前后差异 |
| 复核指标与语义资产 | 指标管理员 | 仅处理本人负责业务域 |
| 恢复发布 | 对应资产发布人 | 重新校验和测评通过后恢复 |

物理字段恢复不会自动恢复指标权限和发布状态，避免未经复核的旧语义重新进入问数链路。

### 7.4 Bad Case 与 Golden

| 操作 | 权限要求 |
| --- | --- |
| 查看问题单 | 提交人、被分配处理人或对应业务域质量运营 |
| 查看原始问题与 Evidence | 同时具备问题单权限和对应数据范围 |
| 修改归因 | 当前处理人或质量运营 |
| 确认 Golden | 质量运营；涉及指标口径时需指标管理员协同 |
| 关闭问题单 | 回归通过且处理人具备关闭权限 |
| 导出问题数据 | 单独授权并完成敏感字段处理 |

问题单权限不能绕过原查询的数据权限。质量运营可以看到定位问题所需的证据，但不因受理问题自动获得其他租户数据。

## 8. 令牌与凭证

DataPath 将不同用途的凭证分开，减少单一凭证泄露后的影响范围。

| 凭证 | 用途 | 核心约束 |
| --- | --- | --- |
| 身份令牌 | 识别前台操作者和角色 | HMAC 签名、到期时间、篡改或过期即失效 |
| 服务令牌 | 保护内部和服务间接口 | Bearer Token，不作为最终用户身份 |
| 查询执行令牌 | 绑定一次已编译查询 | 有效期短，绑定查询运行、操作者和工作空间 |

开发环境可以签发演示身份令牌，非开发环境关闭该入口。后续接入企业身份系统时，身份令牌将由 SSO/OIDC 登录结果换取，角色与数据范围从权限中心读取。

## 9. 失败关闭与用户反馈

权限异常需要给出可行动的提示，但不能暴露未授权资源的存在和内容。

| 场景 | 系统行为 | 面向用户的提示 |
| --- | --- | --- |
| 身份无效或过期 | 不召回、不编译、不执行 | 登录状态已失效，请重新进入 |
| 无业务查询权限 | 不生成可执行查询 | 当前角色不能查询业务数据 |
| 业务域未授权 | 不返回候选指标详情 | 当前问题超出可访问的数据范围 |
| 跨租户访问 | 保留授权范围过滤或直接拒绝 | 无法访问该数据范围 |
| 指标受 Schema 影响 | 阻断查询 | 指标正在复核，暂不可用 |
| 危险写入意图 | 阻断并记录安全事件 | 系统仅支持安全的只读分析 |
| 会话身份变化 | 清空原上下文并重新预检 | 权限已变化，请重新发起查询 |
| 执行令牌过期或不匹配 | 拒绝执行 | 查询已失效，请重新生成 |

## 10. 权限审计

权限系统需要记录“谁在什么时候，以什么权限，对什么资源做了什么”，并能关联到业务结果。

### 10.1 审计对象

- 角色授予、回收和数据范围变更；
- 指标、语义资产和 Join 的创建、修改、发布与下线；
- Schema 影响的确认、修复和恢复；
- Bad Case 分派、归因、Golden 确认和关闭；
- 查询预检失败、跨范围请求和危险意图；
- 查询执行所使用的策略版本、范围指纹和资产版本。

### 10.2 审计字段

| 字段 | 说明 |
| --- | --- |
| `audit_id` | 唯一审计记录 |
| `occurred_at` | 操作时间 |
| `operator_id` / `role_id` | 操作者与当时角色 |
| `workspace_id` / `domain_id` | 工作空间和业务域 |
| `resource_type` / `resource_id` | 资源类型与标识 |
| `action` | 查看、编辑、发布、授权、执行等 |
| `before` / `after` | 变更前后摘要 |
| `scope_fingerprint` | 当时数据范围指纹 |
| `result` / `reason_code` | 成功、拒绝及原因 |
| `trace_id` | 串联接口、查询和 Evidence |

涉及 SQL、查询结果和业务参数时，审计记录只保存定位问题所需的摘要或指纹，避免把敏感数据复制到日志。

## 11. 当前实现与建设计划

### 11.1 已实现

- 签名且带有效期的身份令牌，篡改或过期后查询失败关闭；
- 业务查看者、全国分析师、租户分析师和指标管理员身份策略；
- 工作空间、业务域和业务数据查询权限预检；
- 指标管理员默认不能查询业务数据；
- 租户条件由服务端参数化注入 SQL；
- Query DSL 中的指标、维度和 Join 治理校验；
- 查询执行令牌及操作者、工作空间一致性校验；
- Evidence 中保存角色、范围标签、策略版本和范围指纹；
- 内部接口服务令牌；
- 演示身份签发入口仅在开发环境可用。

### 11.2 上线前 P0

| 建设项 | 原因 | 验收结果 |
| --- | --- | --- |
| 统一治理写接口授权中间件 | 当前本地演示闭环中的部分治理接口尚未统一接入服务端权限校验 | 未授权调用全部返回拒绝，不能仅靠前端隐藏 |
| 权限数据持久化 | 当前角色策略主要由代码配置 | 角色、动作、资源范围可配置并带版本 |
| 权限变更审计 | 支持事故定位和合规追溯 | 授权、回收和范围变化均可查询 |
| 令牌轮换与撤销 | 降低凭证长期有效风险 | 支持密钥轮换、主动失效和短时令牌 |
| 页面能力由服务端返回 | 避免前后端权限口径不一致 | 菜单、按钮和接口使用同一权限声明 |
| 敏感 Evidence 展示控制 | Evidence 可能包含 SQL、参数和结果摘要 | 按角色脱敏，下载需要单独权限 |

### 11.3 后续增强

- 对接企业 SSO/OIDC 与组织架构；
- 支持用户—用户组—角色的批量授权；
- 支持区域、门店、品牌等属性组合的数据策略；
- 指标发布、Golden 确认等高风险操作支持双人复核；
- 权限模拟器：授权前预览用户能够访问的功能和数据；
- 临时权限、到期回收和异常访问告警；
- 对导出、批量查询和高成本查询设置单独权限与配额。

## 12. 验收用例

| 编号 | 用例 | 预期结果 |
| --- | --- | --- |
| PERM-01 | 使用篡改的身份令牌问数 | 请求被阻断，不生成可执行查询 |
| PERM-02 | 使用过期身份令牌问数 | 请求被阻断并提示重新认证 |
| PERM-03 | 指标管理员请求业务数据 | 请求被阻断，但仍可管理授权范围内的指标元数据 |
| PERM-04 | 租户 1 分析师查询订单 | 仅返回租户 1 数据，SQL 使用参数化租户条件 |
| PERM-05 | 租户 1 分析师在问题中要求查看租户 2 | 不扩大数据范围 |
| PERM-06 | 全国分析师查询已授权业务域 | 返回全国范围结果 |
| PERM-07 | 用户查询未授权业务域 | 不返回该域候选指标和数据 |
| PERM-08 | 切换身份后继续原会话 | 原上下文不被继承，重新完成权限预检 |
| PERM-09 | A 用户执行 B 用户的 Query Run | 执行被拒绝 |
| PERM-10 | 使用过期执行令牌 | 执行被拒绝，要求重新编译 |
| PERM-11 | 指标因 Schema 变化进入受影响状态 | 所有角色的相关查询均失败关闭 |
| PERM-12 | 前端直接调用无权治理写接口 | 服务端拒绝并产生审计记录 |
| PERM-13 | 质量运营处理其他租户 Bad Case | 只能看到授权范围内的证据 |
| PERM-14 | 权限管理员授予全国范围 | 产生包含变更前后值的审计记录 |

## 13. 产品判断

对 DataPath 而言，权限不是登录后的附属模块，而是可信答案的一部分。只有当指标口径、Join、Schema 状态和数据范围同时可验证时，系统才能把一条自然语言回答定义为“可信”。

因此，产品的权限建设优先级是：

1. 先保证查询链路在服务端失败关闭；
2. 再完成治理操作的细粒度授权和审计；
3. 最后扩展企业组织、临时授权和复杂属性策略。

这一路径既保留当前原型中已经跑通的租户隔离与职责分离，也为真实企业部署预留了清晰的工程化边界。
