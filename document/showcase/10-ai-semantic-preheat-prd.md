# AI 语义预热 PRD

## 1. 执行摘要

### 1.1 问题陈述

企业指标发布时通常只有名称、公式和业务定义，缺少真实用户会使用的别名、口语问法、反向表达和相邻指标边界。完全人工配置成本高；等待线上问题积累，则会让第一批用户承担冷启动错误。

### 1.2 解决方案

在指标发布前，由 AI 基于已确认的定义、公式、维度和血缘生成语义草稿，系统执行完整度与冲突检查，指标管理员审核后才能应用。AI 只扩展语言覆盖，不修改指标口径、权限、血缘或发布状态。

### 1.3 成功标准

| 类型 | 指标 | MVP 目标 |
| --- | --- | ---: |
| 生成稳定性 | 结构化草稿生成成功率 | ≥ 95% |
| 建议价值 | 直接或修改后采纳率 | ≥ 60% |
| 治理效率 | 单指标语义准备时长 | 较纯人工流程下降 ≥ 30% |
| 召回质量 | 新业务域首轮 Recall@3 | ≥ 90% |
| 安全门禁 | 未审核语义进入生产次数 | 0 |
| 事实边界 | AI 修改公式、血缘或权限次数 | 0 |

上述为下一阶段目标。当前项目已有 62 个审核别名、11 份语义档案和 220 条向量，可作为功能基线，但尚未形成完整的人工效率对照数据。

### 1.4 指标口径

| 指标 | 计算公式与分母 | 数据源 | 观察窗口 |
| --- | --- | --- | --- |
| 结构化草稿生成成功率 | 通过 JSON Schema 和事实字段校验的生成任务数 / 已完成生成任务数；取消任务不进入分母 | 生成任务、Schema 校验日志 | 按版本、周 |
| 建议采纳率 | 被直接接受或人工修改后接受的建议条数 / 已完成审核的建议条数；待审核不进入分母 | `PreheatSuggestion` 审核记录 | 按业务域、月 |
| 单指标语义准备时长 | 从首次生成或人工编辑开始，到语义版本可发布为止的有效操作时长中位数 | 页面埋点、版本审计 | 发布批次 |
| 新业务域首轮 Recall@3 | 正确指标出现在 Top-3 的冷启动用例数 / 冷启动可回答用例数 | 固定冷启动测评集 | 每次语义版本 |
| 相邻指标误召回率 | 负例中错误指标进入 Top-3 的用例数 / 相邻指标负例总数 | 冲突指标专项集 | 每次语义版本 |
| 未审核语义进入生产次数 | 生效资产中缺少审核人与审核版本的记录数 | 资产版本、发布审计 | 实时硬门禁 |

效率下降 30% 采用同一批指标的交叉对照：一组使用纯人工流程，一组使用 AI 草稿流程，并按指标复杂度分层比较中位数。样本量、业务域和执行人员在实验开始前冻结。

## 2. 用户体验与功能

### 2.1 用户角色

| 角色 | 目标 | 核心权限 |
| --- | --- | --- |
| 指标管理员 | 降低语义准备成本并控制业务口径 | 生成、编辑、审核、应用、撤回 |
| 业务负责人 | 确认业务表达是否符合实际 | 查看、评论、确认业务用语 |
| 只读审核员 | 检查生成依据和变更历史 | 查看草稿、差异和审计记录 |

### 2.2 用户故事与验收标准

#### US-01：诊断语义缺口

> 作为指标管理员，我希望在发布前看到语义完整度和具体缺口，从而知道哪些内容需要补充。

验收标准：

- 完整度至少检查业务定义、别名、正向问法、反向样例和相邻指标边界；
- 每个扣分项展示原因和建议，不改变指标公式；
- 缺少必填业务事实时禁止生成，并定位缺失字段；
- 评分规则和版本可追溯。

#### US-02：生成语义草稿

> 作为指标管理员，我希望 AI 基于已确认事实生成草稿，从而不必从空白开始枚举表达。

验收标准：

- 输入只读取已发布或待审核的结构化指标事实；
- 输出包含业务别名、典型正向问法、反向样例和相邻指标区分说明；
- 每条建议包含生成依据、建议类型和置信提示；
- 输出必须符合固定 JSON Schema，失败时可重试但不产生半成品；
- 生成不会直接改变在线召回资产。

#### US-03：审核并应用

> 作为指标管理员，我希望逐条接受、修改或拒绝建议，并在冲突检查通过后统一应用。

验收标准：

- 支持单条和批量接受、修改、拒绝；
- 应用前检查指标名称、别名、相邻指标及保留词冲突；
- 展示应用前后差异、操作人、时间和草稿指纹；
- 未审核、存在冲突或来源指标已变化时禁止应用；
- 应用后生成新语义资产版本并触发索引重建。

#### US-04：撤回与重新生成

> 作为指标管理员，我希望在业务定义变化后撤回旧语义并重新生成，避免过期表达继续参与召回。

验收标准：

- 源指标版本变化后，旧草稿标记为 `STALE`；
- 已应用资产不自动覆盖，需人工复核；
- 撤回后在线召回不再使用对应资产；
- 历史版本和采用记录保留。

#### US-05：业务负责人确认高风险用语

> 作为业务负责人，我希望确认核心指标和高冲突指标的业务表达，从而避免技术上相似但业务上错误的别名进入生产。

验收标准：

- 核心指标、跨业务域共享指标和存在阻断级冲突的草稿必须经过业务负责人确认；
- 指标管理员不能代替业务负责人完成第二审批；
- 普通指标允许指标管理员单人审核，审核策略由业务域配置；
- 审批意见、角色和版本进入审计记录。

### 2.3 主流程

```text
选择指标
→ 读取已确认业务事实
→ 计算语义完整度
→ AI 生成结构化草稿
→ 冲突与安全检查
→ 人工逐条审核
→ 离线固定集验证
→ 应用新语义版本
→ 重建索引并进入正式测评
```

影子召回不属于 MVP。MVP 只使用冻结的离线测评集验证；V1.1 才在不影响线上排序的条件下记录影子召回结果。

### 2.4 语义完整度规则

| 组成项 | 权重 | 最低要求 |
| --- | ---: | --- |
| 业务定义 | 25% | ≥ 40 个有效字符，说明对象、动作和业务含义 |
| 业务别名 | 15% | ≥ 3 条；至少 1 条非缩写业务表达 |
| 正向问法 | 20% | ≥ 5 条；覆盖查值、趋势或排名中的适用类型 |
| 反向样例 | 20% | ≥ 3 条；至少覆盖一个相邻指标 |
| 相邻指标边界 | 20% | 对每个高相似指标说明选择与排除条件 |

语义完整度只反映语言资产准备情况。以下为硬门禁，不能被分数抵消：

- 缺少指标名称、业务定义、单位、时间粒度或公式事实；
- 允许维度与指标定义不一致；
- 存在未解决的阻断级语义冲突；
- 来源指标、模型、Join 或 Schema 处于未发布、过期或受影响状态。

发布建议线为 80 分，但达到 80 分不代表自动发布。

### 2.5 语义冲突规则

| 冲突类型 | 判定 | 级别 | 处理 |
| --- | --- | --- | --- |
| 完全同名 | 同业务域内归一化别名完全一致 | 阻断 | 必须删除、限定范围或增加澄清规则 |
| 正反例自冲突 | 本指标反例能够 Top-3 命中本指标 | 阻断 | 修改反例、别名或区分说明 |
| 相邻指标混淆 | 一条正例同时高置信命中多个相邻指标 | 阻断 | 补充边界并进入澄清专项测评 |
| 保留词冲突 | 建议使用时间、单位、维度等系统保留词 | 阻断 | 禁止应用 |
| 跨业务域同名 | 不同业务域存在相同表达 | 提示 | 要求业务域上下文明确；无上下文时澄清 |
| 高语义相似 | 归一化后未同名，但超过配置相似阈值 | 提示 | 人工复核并记录处理结论 |

归一化至少包含大小写、全半角、空格、常用标点和已登记缩写处理。相似阈值及归一化规则必须版本化。

### 2.6 状态机

| 状态 | 含义 | 允许动作 |
| --- | --- | --- |
| `NOT_GENERATED` | 尚无草稿 | 生成 |
| `GENERATING` | AI 正在处理 | 查看进度、取消 |
| `DRAFT` | 草稿待审核 | 编辑、接受、拒绝 |
| `CONFLICTED` | 存在语义冲突 | 修正、重新检查 |
| `APPROVED` | 人工审核通过 | 离线验证 |
| `VALIDATING` | 正在运行离线测评 | 查看结果、取消 |
| `VALIDATION_FAILED` | 固定集或安全用例失败 | 修正、重新验证 |
| `VALIDATED` | 离线测评和安全门禁通过 | 应用 |
| `APPLIED` | 已生成语义版本 | 撤回、重新生成 |
| `REJECTED` | 整份草稿被拒绝 | 查看原因、复制后重建 |
| `ROLLED_BACK` | 已回滚到上一稳定版本 | 查看、重新生成 |
| `STALE` | 来源事实已变化 | 复核、废弃 |
| `FAILED` | 生成或校验失败 | 查看原因、重试 |

#### 状态迁移

| 当前状态 | 动作 | 下一状态 | 操作角色 | 服务端前置条件 |
| --- | --- | --- | --- | --- |
| `NOT_GENERATED/FAILED` | 发起生成 | `GENERATING` | 指标管理员 | 业务事实完整且资产可用 |
| `GENERATING` | 生成成功 | `DRAFT` | 系统 | Schema 与事实校验通过 |
| `DRAFT` | 完成冲突检查 | `APPROVED` 或 `CONFLICTED` | 指标管理员/系统 | 审核完成；高风险项完成双人确认 |
| `APPROVED` | 发起验证 | `VALIDATING` | 指标管理员 | 来源指纹未变化 |
| `VALIDATING` | 测评完成 | `VALIDATED` 或 `VALIDATION_FAILED` | 系统 | 固定集、安全门禁和索引预检完成 |
| `VALIDATED` | 应用版本 | `APPLIED` | 指标管理员 | 来源指纹未变化且审批仍有效 |
| `APPLIED` | 撤回 | `ROLLED_BACK` | 指标管理员 | 上一稳定版本存在 |
| 任意非终态 | 来源变化 | `STALE` | 系统 | 指标或依赖资产版本变化 |

### 2.7 页面状态

| 页面状态 | 必须展示 |
| --- | --- |
| 空状态 | 适用条件、所需业务事实、生成入口 |
| 生成中 | 任务阶段、耗时、取消入口，不展示半成品 |
| 待审核 | 建议分组、生成依据、接受/修改/拒绝和差异 |
| 冲突 | 冲突对象、级别、处理建议和重新检查入口 |
| 验证失败 | 失败用例、实际命中、预期结果和修复入口 |
| 来源过期 | 变化字段、旧版本、新版本和重新生成入口 |
| 无权限 | 可申请的角色，不泄露其他业务域资产 |

### 2.8 异常规则

| 异常 | 产品处理 |
| --- | --- |
| 模型超时或输出不符合 Schema | 标记 `FAILED`，保留输入指纹并允许重试 |
| 指标定义不完整 | 阻止生成，跳转缺失字段 |
| 新别名与其他指标冲突 | 标记 `CONFLICTED`，禁止批量应用 |
| 审核期间指标版本变化 | 草稿转 `STALE`，要求重新生成 |
| 索引重建失败 | 不切换在线版本，保留上一稳定版本 |

### 2.9 跨模块依赖

| 方向 | 依赖或输出 | 失败处理 |
| --- | --- | --- |
| 上游：指标中心 | 指标版本、定义、单位、维度和血缘 | 缺失或未发布时禁止生成 |
| 上游：Schema 管理 | 模型、字段和 Join 可用状态 | 任一依赖 `IMPACTED` 时草稿转 `STALE` |
| 下游：问数检索 | 审核并验证后的语义资产版本 | 索引切换失败时保留上一版本 |
| 下游：Bad Case | 语义资产版本和建议来源 | 线上问题必须能追溯到应用版本 |
| 回流：Golden | 已确认的正反例和冲突边界 | 只生成修复建议，不自动应用 |

### 2.10 非目标

- AI 自动创建或修改指标公式；
- AI 自动变更 Join、血缘、权限或发布状态；
- 未经审核自动学习所有线上问法；
- 使用生成数量代替召回和误召回评测；
- 建设通用企业知识库。

## 3. AI 系统要求

### 3.1 输入与输出

输入包括指标 ID 与版本、名称、业务定义、公式只读摘要、单位、时间粒度、允许维度、血缘、已有别名、正反例和相邻指标。

输出必须结构化为：

- `aliases[]`：建议别名及依据；
- `positive_queries[]`：应命中本指标的典型问法；
- `negative_queries[]`：不应命中本指标的反例；
- `distinctions[]`：与相邻指标的边界说明；
- `warnings[]`：缺失事实、冲突或低置信提示。

### 3.2 模型边界

- 模型只能在给定事实范围内扩展语言；
- 不得补造业务规则、枚举值或可查询维度；
- 不得输出可执行 SQL；
- 对信息不足的内容输出缺口，不进行猜测；
- 所有应用动作由确定性服务端规则控制。

### 3.3 评测策略

| 评测层 | 方法 | 通过条件 |
| --- | --- | --- |
| 格式 | JSON Schema 校验 | 100% 合法后才进入审核 |
| 事实一致性 | 与指标定义、单位、维度逐项对照 | 不得改变业务事实 |
| 语义有效性 | 人工接受、修改、拒绝统计 | 采纳率达到目标 |
| 检索收益 | 应用前后固定用例 A/B | Recall@3 提升且误召回不恶化 |
| Top-1 正确性 | 正确指标首次命中 | 不低于应用前基线 |
| 负例质量 | 相邻指标负例与澄清用例 | 误召回率不高于门限，错误指标选择为 0 |
| 安全 | 越权、未发布、冲突资产用例 | 错误放行 0 |

### 3.4 模型与工具要求

- 模型必须支持固定 JSON Schema 输出或可被确定性解析器严格校验；
- Prompt、模型、温度、检索资产和完整度规则均记录版本；
- 模型只通过指标事实读取工具获得输入，不能直接访问明细数仓；
- 生成任务必须支持超时、有限重试、幂等键和成本记录；
- 更换模型或 Prompt 后必须重新运行格式、事实一致性、相邻指标与安全专项集；
- 模型不可用时允许人工维护语义资产，不影响已有在线版本。

## 4. 技术规格

### 4.1 架构与数据流

```text
指标中心 → 事实快照 → Prompt/Schema 组装 → LLM
    ↓                                      ↓
完整度服务 ← 结构化草稿 ← Schema 校验与冲突检查
    ↓
审核工作台 → 语义资产版本 → 混合检索索引 → 正式测评
```

### 4.2 核心实体

| 实体 | 关键字段 |
| --- | --- |
| `SemanticProfile` | metric_id、metric_version、completeness_score、rule_version |
| `PreheatDraft` | source_fingerprint、model_version、status、created_by |
| `PreheatSuggestion` | type、content、rationale、review_status、reviewer |
| `SemanticAssetVersion` | version、approved_items、effective_at、rollback_to |

### 4.3 集成点

- 指标中心：读取业务事实与版本；
- 语义检索：应用审核后的别名和样例；
- 测评服务：运行冷启动、相邻指标和安全用例；
- 权限服务：限制生成、审核和应用动作；
- 审计服务：记录生成输入、模型版本、差异和操作者。

### 4.4 安全与隐私

- 仅发送生成所需的最小字段，不发送原始明细数据；
- 租户、工作区和业务域严格隔离；
- Prompt、模型响应和人工修改均保留审计摘要；
- 前端隐藏按钮不能替代服务端权限校验；
- API 密钥与业务数据分离存储。

### 4.5 性能与可靠性目标

| 场景 | 目标 |
| --- | ---: |
| 完整度计算 P95 | ≤ 1 秒 |
| 单指标生成 P95 | ≤ 30 秒 |
| 冲突检查 P95 | ≤ 2 秒 |
| 应用失败后的在线影响 | 0，继续使用上一稳定版本 |

## 5. 风险与路线图

### 5.1 分阶段发布

- **MVP**：完整度、单指标生成、逐条审核、冲突检查、离线固定集验证和版本应用；
- **V1.1**：批量生成、影子召回、相邻指标自动推荐和效率看板；
- **V2.0**：基于已确认 Bad Case 推荐补充语义，但仍保持人工发布。

### 5.2 灰度策略

MVP 先只生成不应用，再使用冻结离线集验证；固定用例通过后，对一个非核心业务域开放人工应用，最后按业务域逐步放量。V1.1 再增加不影响线上排序的影子召回，用于比较真实表达覆盖。任一阶段出现错误指标选择、安全门禁失败或误召回显著上升，立即回滚语义资产版本。

### 5.3 主要风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 生成内容看似丰富但无检索收益 | 增加审核成本 | 以 A/B 召回收益和采纳率评估 |
| 反例质量不足 | 相邻指标误召回 | 纳入冲突指标专项集 |
| 审核成为新瓶颈 | 上线速度无改善 | 批量操作、差异视图和风险排序 |
| 过期草稿被应用 | 污染线上语义 | 来源指纹和版本门禁 |
