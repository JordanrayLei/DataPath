# Schema 影响管理 PRD

## 1. 执行摘要

### 1.1 问题陈述

企业数仓持续发生删表、删字段、重命名和类型变化。若 ChatBI 只在查询报错时发现问题，旧指标、Join 和语义模型可能继续返回错误或不完整答案，治理人员也无法快速判断影响范围。

### 1.2 解决方案

将 Schema 变化作为一等产品事件：重新扫描物理结构、识别差异、沿血缘传播影响、降级受影响业务域并阻断查询。即使物理结构恢复，也必须由负责人复核相关模型、Join、指标和语义资产后重新发布。

### 1.3 成功标准

| 类型 | 指标 | MVP 目标 |
| --- | --- | ---: |
| 发现 | 已配置数据源破坏性变化识别率 | 100% |
| 传播 | 已知依赖资产影响覆盖率 | 100% |
| 安全 | 受影响资产继续执行次数 | 0 |
| 恢复 | 未复核资产自动恢复次数 | 0 |
| 效率 | Schema Diff 生成到影响传播完成 P95 | ≤ 5 分钟 |
| 可追溯 | 变化、影响、处置和重发审计覆盖率 | 100% |

当前项目已经覆盖真实 DDL 删除表、删除字段和修改类型的工程验证；上述运营时效指标属于下一阶段目标。

### 1.4 指标口径

| 指标 | 计算公式与分母 | 数据源 | 观察窗口 |
| --- | --- | --- | --- |
| 破坏性变化识别率 | 正确识别的破坏性变化数 / DDL 验收集中破坏性变化总数 | 冻结 DDL 验收集、`SchemaChangeEvent` | 每次规则版本 |
| 已登记依赖影响覆盖率 | 正确识别的受影响资产数 / 验收集预期受影响资产数 | 依赖图、验收 Oracle | 每次规则版本 |
| 影响误报率 | 被错误标记为受影响的资产数 / 系统标记的受影响资产数 | 人工复核结果 | 每次扫描、月 |
| 受影响资产继续执行次数 | 执行时依赖任一 `IMPACTED` 资产的查询数 | Query Gate、执行审计 | 实时硬门禁 |
| 影响传播耗时 | `diff_created_at` 至 `impact_completed_at` | 变化事件与影响任务 | 按扫描、周 |
| 检测延迟 | `change_occurred_at` 至 `diff_created_at`；无法获得 DDL 时间时单独标记未知 | DDL 通知或扫描快照 | 定时扫描启用后 |
| 审计覆盖率 | 具有变化证据、影响清单、处置、验证和审批记录的已关闭事件数 / 已关闭事件总数 | 审计日志 | 月 |

“100%”仅指冻结验收集和已登记依赖构成的封闭范围，不宣称能够覆盖系统未知的外部血缘。未知依赖数量单独监控，不计入已登记依赖覆盖率。

## 2. 用户体验与功能

### 2.1 用户角色

| 角色 | 目标 | 核心权限 |
| --- | --- | --- |
| 数据平台管理员 | 发现变化并修复物理资产 | 扫描、确认变化、分派 |
| 指标管理员 | 复核受影响模型、Join 和指标 | 查看影响、修复、重发 |
| 业务用户 | 不使用过期资产得到错误答案 | 查看阻断原因和恢复状态 |
| 只读审核员 | 追溯变化和处置过程 | 查看影响图与审计 |

### 2.2 用户故事与验收标准

#### US-01：识别 Schema 差异

> 作为数据平台管理员，我希望重新扫描后看到准确的物理变化，从而及时判断风险。

验收标准：

- 识别新增、删除、重命名候选、类型变化和可空性变化；
- 明确区分破坏性与非破坏性变化；
- 保存扫描前后快照、DDL 证据、数据源和发生时间；
- 重命名只作为候选建议，未经确认不得自动迁移依赖。

#### US-02：查看影响传播

> 作为指标管理员，我希望看到变化影响了哪些模型、Join、指标和问数用例，从而按风险修复。

验收标准：

- 影响链至少覆盖物理表 → 语义模型 → Join → 指标 → 语义资产 → Golden；
- 展示直接影响和间接影响；
- 每项资产显示负责人、当前状态、影响原因和建议动作；
- 支持按业务域、严重级别、负责人和状态筛选。

#### US-03：失败关闭

> 作为业务用户，我希望系统在资产失效时明确阻断，而不是返回猜测答案。

验收标准：

- 受影响指标、模型或 Join 不进入候选和执行；
- 已进入执行链路的请求在服务端门禁再次校验；
- 返回 `BLOCKED`、受影响资产类型和处理建议；
- 不暴露无权限的表名、字段名或其他业务域资产。

#### US-04：修复与恢复

> 作为指标管理员，我希望修复后逐项复核并重新发布，避免底层字段恢复就自动放行。

验收标准：

- 支持确认替代字段、修复模型映射、Join 和指标；
- 物理结构恢复只将事件标记为“可复核”，不恢复服务；
- 相关 Golden 与安全用例全部通过后才能重发；
- 重发记录关联变化事件、修复版本、验证结果和审批人。

#### US-05：按风险分派与升级

> 作为数据平台管理员，我希望变化事件自动关联负责人和处置时限，从而避免受影响资产长期无人处理。

验收标准：

- 事件按严重级别生成确认与修复 SLA；
- 超时后通知业务域负责人并升级到平台管理员；
- 无负责人资产进入独立队列，不得因无人负责自动恢复；
- 负责人、转派、超时和升级记录可审计。

### 2.3 主流程

```text
触发重新扫描
→ 生成物理快照
→ 计算 Schema Diff
→ 判定破坏性等级
→ 沿依赖图传播影响
→ 资产转 IMPACTED / 业务域转 DEGRADED
→ 在线查询失败关闭
→ 负责人修复并复核
→ 运行受影响 Golden 与安全用例
→ 审批并重新发布
→ 关闭变化事件
```

### 2.4 变化与影响规则

| 变化类型 | 默认等级 | 默认处理 |
| --- | --- | --- |
| 新增表或字段 | 低 | 记录，不影响现有服务 |
| 删除未引用字段 | 低 | 记录并提示，不阻断现有服务 |
| 删除被引用字段 | 高 | 传播影响并立即阻断 |
| 删除被引用表 | 严重 | 业务域降级并阻断相关查询 |
| 数值精度或字符串长度扩大 | 低 | 记录并运行抽样验证 |
| 数值精度或字符串长度缩小 | 高 | 阻断依赖指标并验证截断风险 |
| `nullable` 变为 `non-nullable` | 中 | 检查数据与 DSL 假设后决定 |
| `non-nullable` 变为 `nullable` | 高 | 阻断依赖聚合并验证空值处理 |
| 主键、唯一键或 Join Key 变化 | 严重 | 阻断相关 Join 和所有下游指标 |
| 默认值或枚举值变化 | 中 | 标记语义风险并运行受影响 Golden |
| 类型兼容变化 | 中 | 按类型白名单运行受影响回归 |
| 类型不兼容变化 | 高 | 阻断相关模型和指标 |
| 表迁移至其他 Schema | 高 | 按删除+新增处理，人工确认映射 |
| 重命名候选 | 高 | 人工确认映射前按删除+新增处理 |

类型兼容白名单按数据仓库方言版本化。未命中白名单的变化默认按不兼容处理。

### 2.5 阻断范围规则

| 条件 | 默认阻断范围 |
| --- | --- |
| 单字段且依赖完整 | 直接引用该字段的模型、指标和查询 |
| Join Key 或共享维度变化 | 相关 Join 及所有下游指标 |
| 表删除 | 引用该表的模型及其下游资产 |
| 血缘存在未知节点 | 从最后一个可信节点向下游阻断，并将业务域标为 `DEGRADED` |
| 多个核心资产同时受影响 | 业务域 `BLOCKED` |

系统不因单个未知依赖默认阻断整个工作区。只有无法确定安全边界，或核心指标、共享 Join 受到影响时，才升级到业务域级阻断。

人工例外只允许对已证明不读取受影响字段的非核心资产临时放行，最长 24 小时，必须由数据平台管理员与指标管理员双人批准并记录依据。核心指标、权限、Join Key 和安全用例不得例外。

### 2.6 状态机

| 状态 | 含义 | 允许动作 |
| --- | --- | --- |
| `DETECTED` | 已发现变化 | 查看、确认等级 |
| `IMPACT_ASSESSED` | 已生成影响清单 | 分派、阻断 |
| `REMEDIATING` | 修复中 | 更新映射、模型和指标 |
| `READY_FOR_REVIEW` | 物理与逻辑修复完成 | 复核、测评 |
| `VALIDATED` | 回归通过 | 审批重发 |
| `RESOLVED` | 已恢复服务 | 查看审计 |
| `REJECTED` | 非真实变化或误报 | 记录理由 |
| `FAILED` | 扫描、Diff 或传播失败 | 查看阶段、重试 |

资产状态独立使用 `ACTIVE`、`IMPACTED`、`DEPRECATED`；业务域使用 `ACTIVE`、`DEGRADED`、`BLOCKED`。

#### 状态迁移

| 当前状态 | 动作 | 下一状态 | 操作角色 | 服务端前置条件 |
| --- | --- | --- | --- | --- |
| 无事件 | 完成 Diff | `DETECTED` | 系统 | 快照完整且 Diff 可重放 |
| `DETECTED` | 传播影响 | `IMPACT_ASSESSED` | 系统 | 影响任务完成或明确标记未知依赖 |
| `IMPACT_ASSESSED` | 接受任务 | `REMEDIATING` | 负责人 | 阻断状态已生效 |
| `REMEDIATING` | 提交复核 | `READY_FOR_REVIEW` | 数据/指标管理员 | 修复版本与变化事件绑定 |
| `READY_FOR_REVIEW` | 运行测评 | `VALIDATED` 或退回 `REMEDIATING` | 系统/审核员 | 受影响 Golden 与安全用例完成 |
| `VALIDATED` | 审批重发 | `RESOLVED` | 发布审核员 | 双人审批、资产新版本可用 |
| 任意处理中状态 | 新变化到达 | `DETECTED` | 系统 | 新事件关联原事件并使旧验证失效 |

### 2.7 页面状态

| 页面状态 | 必须展示 |
| --- | --- |
| 无变化 | 最近扫描时间、快照版本、重新扫描入口 |
| 扫描中 | 扫描阶段、数据源、开始时间和取消规则 |
| 已发现 | Before/After、严重度、证据和受影响数量 |
| 传播不完整 | 未知依赖、当前阻断边界和人工检查入口 |
| 修复中 | 负责人、SLA、资产清单和任务状态 |
| 验证失败 | 失败 Golden、安全用例和实际结果 |
| 已恢复 | 新版本、审批人、恢复时间和完整审计链 |
| 无权限 | 业务化阻断原因，不暴露物理字段 |

### 2.8 异常与幂等规则

| 异常 | 产品处理 |
| --- | --- |
| 扫描中断 | 不覆盖上一快照，事件标记失败 |
| 血缘图不完整 | 提升风险等级并扩大阻断范围 |
| 影响传播超时 | 保持受影响业务域降级，不允许放行 |
| 回归失败 | 保持 `IMPACTED`，展示失败 Golden |
| 修复后再次变化 | 创建新事件并关联原事件 |
| 同一 Diff 重复上报 | 通过 source、before_hash、after_hash 幂等合并 |
| 扫描任务并发 | 同一数据源只允许一个写入快照的任务，其余转只读或排队 |
| 旧扫描晚于新扫描完成 | 不覆盖新快照，记录为过期任务 |
| 多个事件影响同一资产 | 合并展示原因；全部事件解决前资产保持 `IMPACTED` |

### 2.9 严重级别与 SLA

| 级别 | 确认 SLA | 目标修复时间 | 升级对象 |
| --- | ---: | ---: | --- |
| 低 | 2 个工作日 | 下一维护周期 | 资产负责人 |
| 中 | 1 个工作日 | 3 个工作日 | 业务域负责人 |
| 高 | 2 小时 | 1 个工作日 | 数据平台管理员 |
| 严重 | 30 分钟 | 4 小时内给出处置方案 | 平台负责人和业务负责人 |

SLA 为下一阶段运营目标，不作为当前项目已有结果。

### 2.10 跨模块依赖

| 方向 | 依赖或输出 | 失败处理 |
| --- | --- | --- |
| 上游：数据源扫描 | 物理快照、方言和采集时间 | 快照不完整时不生成新 Diff |
| 上游：治理资产 | 模型、Join、指标和血缘 | 未知依赖采用保守边界并告警 |
| 下游：问数服务 | 资产与业务域状态 | `IMPACTED` 资产候选和执行双重阻断 |
| 下游：AI 预热 | 来源指标与模型状态 | 相关草稿转 `STALE` |
| 下游：Bad Case/Golden | 受影响用例范围 | Schema 事件未解决时修复发布保持 `BLOCKED` |

### 2.11 非目标

- 自动修改生产数仓 DDL；
- 自动确认字段重命名；
- 自动改写指标公式；
- 物理字段恢复后自动恢复服务；
- 替代企业完整的数据目录或数据血缘平台。

## 3. AI 系统要求

AI 不是该模块的决策主体。可用于解释 DDL、推荐重命名候选和总结影响，但以下行为必须由确定性系统完成：

- 计算 Schema Diff；
- 解析字段引用与依赖图；
- 判定资产是否可查询；
- 控制状态迁移和重发门禁。

### 3.1 AI 辅助要求

- 建议必须附带来源字段、相似依据和置信提示；
- 不得自动接受重命名映射；
- 不得自动修改模型、Join 或指标；
- 模型不可用时不影响差异识别、阻断和恢复主流程。

### 3.2 评测策略

| 用例 | 预期 |
| --- | --- |
| 删除被指标引用的字段 | 指标转 `IMPACTED`，查询 `BLOCKED` |
| 删除 Join Key | Join 和所有依赖指标被阻断 |
| 不兼容类型变化 | 传播影响，不执行旧 DSL |
| 新增未引用字段 | 记录变化，不误伤现有查询 |
| 原字段恢复 | 保持阻断，直至人工复核和重发 |
| 无权限用户查看影响 | 不泄露物理结构 |
| 重复上报同一 Diff | 只保留一个活动事件 |
| 旧扫描结果晚到 | 不覆盖当前快照 |
| 多个事件影响同一资产 | 任一未解决时仍保持阻断 |

## 4. 技术规格

### 4.1 架构与数据流

```text
Warehouse → Scanner → PhysicalSnapshot → SchemaDiff
                                      ↓
Dependency Graph → Impact Engine → Asset State Store
                                      ↓
Query Gate ← Domain Status ← Review / Evaluation / Publish
```

### 4.2 核心实体

| 实体 | 关键字段 |
| --- | --- |
| `PhysicalSnapshot` | source_id、schema_hash、captured_at |
| `SchemaChangeEvent` | change_type、before、after、severity、status |
| `AssetDependency` | upstream_id、downstream_id、dependency_type |
| `ImpactRecord` | event_id、asset_id、reason、owner、resolution |
| `RecoveryApproval` | evaluation_run、reviewer、approved_version |

`SchemaChangeEvent` 还必须包含 `source_id`、`before_hash`、`after_hash`、`detected_at`、`change_occurred_at`（可空）、`rule_version` 和 `supersedes_event_id`，用于幂等、时效和并发处理。

### 4.3 集成点

- 数据源扫描器：生成结构快照；
- 业务域与模型中心：维护资产状态；
- Join Graph：提供关系与 Key 依赖；
- 指标中心：提供公式字段和血缘；
- 问数服务：候选与执行前双重门禁；
- 测评服务：运行受影响 Golden；
- 权限与审计：控制查看、修复和重发。

### 4.4 安全与隐私

- 影响页按工作区、业务域和资源权限裁剪；
- 业务用户只看到可理解的阻断原因；
- DDL、字段映射和审批全量审计；
- 扫描凭证只读且与应用凭证隔离；
- 任何客户端状态都不能绕过服务端资产门禁。

### 4.5 性能与可靠性目标

| 场景 | 目标 |
| --- | ---: |
| 中型业务域 Diff P95 | ≤ 60 秒 |
| 影响清单查询 P95 | ≤ 2 秒 |
| 在线资产状态校验 P95 | ≤ 50 毫秒 |
| 阻断一致性 | 所有实例最终一致时间 ≤ 30 秒 |

性能目标的规模基线为单业务域不超过 50 张表、1,000 个字段、500 个治理资产和 2,000 条依赖边；超过该规模需单独记录，不纳入当前 P95。

## 5. 风险与路线图

### 5.1 分阶段发布

- **MVP**：手动扫描、删除/类型变化识别、影响传播、失败关闭、人工恢复；
- **V1.1**：定时扫描、负责人分派、影响图和受影响 Golden 自动选择；
- **V2.0**：接入变更通知、发布前影响预演和跨业务域风险看板。

### 5.2 灰度与回滚

先在验收业务域以影子方式计算影响；与人工清单一致后启用告警；再开启查询阻断。传播规则升级时保留上一规则版本，若误阻断超过阈值，回滚规则但不绕过已确认的真实破坏性事件。

### 5.3 主要风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 血缘缺失导致漏报 | 错误答案继续服务 | 对未知依赖采用保守阻断 |
| 误报导致大面积阻断 | 影响业务可用性 | 影子验证、严重度分级、人工确认 |
| 修复流程过长 | 业务恢复慢 | 负责人、SLA、批量验证与明确交接 |
| 仅恢复物理字段但语义已过期 | 错误重新上线 | 强制复核和版本重发 |
