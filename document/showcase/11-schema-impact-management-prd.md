# Schema 影响管理 PRD

## 1. 执行摘要

### 1.1 问题陈述

企业数仓持续发生删表、删字段、重命名和类型变化。若 ChatBI 只在查询报错时发现问题，旧指标、Join 和语义模型可能继续返回错误或不完整答案，治理人员也无法快速判断影响范围。

### 1.2 解决方案

将 Schema 变化作为一等产品事件：重新扫描物理结构、识别差异、沿血缘传播影响、降级受影响业务域并阻断查询。即使物理结构恢复，也必须由负责人复核相关模型、Join、指标和语义资产后重新发布。

### 1.3 成功标准

| 类型 | 指标 | MVP 目标 |
| --- | --- | ---: |
| 发现 | 已配置数据源破坏性变化识别率 | 100% |
| 传播 | 已知依赖资产影响覆盖率 | 100% |
| 安全 | 受影响资产继续执行次数 | 0 |
| 恢复 | 未复核资产自动恢复次数 | 0 |
| 效率 | 变化发现到影响清单生成 P95 | ≤ 5 分钟 |
| 可追溯 | 变化、影响、处置和重发审计覆盖率 | 100% |

当前项目已经覆盖真实 DDL 删除表、删除字段和修改类型的工程验证；上述运营时效指标属于下一阶段目标。

## 2. 用户体验与功能

### 2.1 用户角色

| 角色 | 目标 | 核心权限 |
| --- | --- | --- |
| 数据平台管理员 | 发现变化并修复物理资产 | 扫描、确认变化、分派 |
| 指标管理员 | 复核受影响模型、Join 和指标 | 查看影响、修复、重发 |
| 业务用户 | 不使用过期资产得到错误答案 | 查看阻断原因和恢复状态 |
| 只读审核员 | 追溯变化和处置过程 | 查看影响图与审计 |

### 2.2 用户故事与验收标准

#### US-01：识别 Schema 差异

> 作为数据平台管理员，我希望重新扫描后看到准确的物理变化，从而及时判断风险。

验收标准：

- 识别新增、删除、重命名候选、类型变化和可空性变化；
- 明确区分破坏性与非破坏性变化；
- 保存扫描前后快照、DDL 证据、数据源和发生时间；
- 重命名只作为候选建议，未经确认不得自动迁移依赖。

#### US-02：查看影响传播

> 作为指标管理员，我希望看到变化影响了哪些模型、Join、指标和问数用例，从而按风险修复。

验收标准：

- 影响链至少覆盖物理表 → 语义模型 → Join → 指标 → 语义资产 → Golden；
- 展示直接影响和间接影响；
- 每项资产显示负责人、当前状态、影响原因和建议动作；
- 支持按业务域、严重级别、负责人和状态筛选。

#### US-03：失败关闭

> 作为业务用户，我希望系统在资产失效时明确阻断，而不是返回猜测答案。

验收标准：

- 受影响指标、模型或 Join 不进入候选和执行；
- 已进入执行链路的请求在服务端门禁再次校验；
- 返回 `BLOCKED`、受影响资产类型和处理建议；
- 不暴露无权限的表名、字段名或其他业务域资产。

#### US-04：修复与恢复

> 作为指标管理员，我希望修复后逐项复核并重新发布，避免底层字段恢复就自动放行。

验收标准：

- 支持确认替代字段、修复模型映射、Join 和指标；
- 物理结构恢复只将事件标记为“可复核”，不恢复服务；
- 相关 Golden 与安全用例全部通过后才能重发；
- 重发记录关联变化事件、修复版本、验证结果和审批人。

### 2.3 主流程

```text
触发重新扫描
→ 生成物理快照
→ 计算 Schema Diff
→ 判定破坏性等级
→ 沿依赖图传播影响
→ 资产转 IMPACTED / 业务域转 DEGRADED
→ 在线查询失败关闭
→ 负责人修复并复核
→ 运行受影响 Golden 与安全用例
→ 审批并重新发布
→ 关闭变化事件
```

### 2.4 变化与影响规则

| 变化类型 | 默认等级 | 默认处理 |
| --- | --- | --- |
| 新增表或字段 | 低 | 记录，不影响现有服务 |
| 删除未引用字段 | 中 | 提醒负责人复核 |
| 删除被引用字段 | 高 | 传播影响并立即阻断 |
| 删除被引用表 | 严重 | 业务域降级并阻断相关查询 |
| 类型兼容变化 | 中 | 运行受影响回归后决定 |
| 类型不兼容变化 | 高 | 阻断相关模型和指标 |
| 重命名候选 | 高 | 人工确认映射前按删除+新增处理 |

### 2.5 状态机

| 状态 | 含义 | 允许动作 |
| --- | --- | --- |
| `DETECTED` | 已发现变化 | 查看、确认等级 |
| `IMPACT_ASSESSED` | 已生成影响清单 | 分派、阻断 |
| `REMEDIATING` | 修复中 | 更新映射、模型和指标 |
| `READY_FOR_REVIEW` | 物理与逻辑修复完成 | 复核、测评 |
| `VALIDATED` | 回归通过 | 审批重发 |
| `RESOLVED` | 已恢复服务 | 查看审计 |
| `REJECTED` | 非真实变化或误报 | 记录理由 |

资产状态独立使用 `ACTIVE`、`IMPACTED`、`DEPRECATED`；业务域使用 `ACTIVE`、`DEGRADED`、`BLOCKED`。

### 2.6 异常规则

| 异常 | 产品处理 |
| --- | --- |
| 扫描中断 | 不覆盖上一快照，事件标记失败 |
| 血缘图不完整 | 提升风险等级并扩大阻断范围 |
| 影响传播超时 | 保持受影响业务域降级，不允许放行 |
| 回归失败 | 保持 `IMPACTED`，展示失败 Golden |
| 修复后再次变化 | 创建新事件并关联原事件 |

### 2.7 非目标

- 自动修改生产数仓 DDL；
- 自动确认字段重命名；
- 自动改写指标公式；
- 物理字段恢复后自动恢复服务；
- 替代企业完整的数据目录或数据血缘平台。

## 3. AI 系统要求

AI 不是该模块的决策主体。可用于解释 DDL、推荐重命名候选和总结影响，但以下行为必须由确定性系统完成：

- 计算 Schema Diff；
- 解析字段引用与依赖图；
- 判定资产是否可查询；
- 控制状态迁移和重发门禁。

### 3.1 AI 辅助要求

- 建议必须附带来源字段、相似依据和置信提示；
- 不得自动接受重命名映射；
- 不得自动修改模型、Join 或指标；
- 模型不可用时不影响差异识别、阻断和恢复主流程。

### 3.2 评测策略

| 用例 | 预期 |
| --- | --- |
| 删除被指标引用的字段 | 指标转 `IMPACTED`，查询 `BLOCKED` |
| 删除 Join Key | Join 和所有依赖指标被阻断 |
| 不兼容类型变化 | 传播影响，不执行旧 DSL |
| 新增未引用字段 | 记录变化，不误伤现有查询 |
| 原字段恢复 | 保持阻断，直至人工复核和重发 |
| 无权限用户查看影响 | 不泄露物理结构 |

## 4. 技术规格

### 4.1 架构与数据流

```text
Warehouse → Scanner → PhysicalSnapshot → SchemaDiff
                                      ↓
Dependency Graph → Impact Engine → Asset State Store
                                      ↓
Query Gate ← Domain Status ← Review / Evaluation / Publish
```

### 4.2 核心实体

| 实体 | 关键字段 |
| --- | --- |
| `PhysicalSnapshot` | source_id、schema_hash、captured_at |
| `SchemaChangeEvent` | change_type、before、after、severity、status |
| `AssetDependency` | upstream_id、downstream_id、dependency_type |
| `ImpactRecord` | event_id、asset_id、reason、owner、resolution |
| `RecoveryApproval` | evaluation_run、reviewer、approved_version |

### 4.3 集成点

- 数据源扫描器：生成结构快照；
- 业务域与模型中心：维护资产状态；
- Join Graph：提供关系与 Key 依赖；
- 指标中心：提供公式字段和血缘；
- 问数服务：候选与执行前双重门禁；
- 测评服务：运行受影响 Golden；
- 权限与审计：控制查看、修复和重发。

### 4.4 安全与隐私

- 影响页按工作区、业务域和资源权限裁剪；
- 业务用户只看到可理解的阻断原因；
- DDL、字段映射和审批全量审计；
- 扫描凭证只读且与应用凭证隔离；
- 任何客户端状态都不能绕过服务端资产门禁。

### 4.5 性能与可靠性目标

| 场景 | 目标 |
| --- | ---: |
| 中型业务域 Diff P95 | ≤ 60 秒 |
| 影响清单查询 P95 | ≤ 2 秒 |
| 在线资产状态校验 P95 | ≤ 50 毫秒 |
| 阻断一致性 | 所有实例最终一致时间 ≤ 30 秒 |

## 5. 风险与路线图

### 5.1 分阶段发布

- **MVP**：手动扫描、删除/类型变化识别、影响传播、失败关闭、人工恢复；
- **V1.1**：定时扫描、负责人分派、影响图和受影响 Golden 自动选择；
- **V2.0**：接入变更通知、发布前影响预演和跨业务域风险看板。

### 5.2 灰度与回滚

先在验收业务域以影子方式计算影响；与人工清单一致后启用告警；再开启查询阻断。传播规则升级时保留上一规则版本，若误阻断超过阈值，回滚规则但不绕过已确认的真实破坏性事件。

### 5.3 主要风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 血缘缺失导致漏报 | 错误答案继续服务 | 对未知依赖采用保守阻断 |
| 误报导致大面积阻断 | 影响业务可用性 | 影子验证、严重度分级、人工确认 |
| 修复流程过长 | 业务恢复慢 | 负责人、SLA、批量验证与明确交接 |
| 仅恢复物理字段但语义已过期 | 错误重新上线 | 强制复核和版本重发 |
