# PRD：Bad Case 自助闭环

## 1. 背景

ChatBI 上线后会不断遇到用户表达、指标口径、上下文、查询执行和解读方面的问题。普通点赞或点踩只能记录用户态度，无法回答：

- 正确指标到底是什么？
- 系统应该成功、澄清、拒绝还是阻断？
- 错误发生在召回、裁决、DSL、执行还是解读阶段？
- 修复当前问题后，是否破坏了其他问题？
- 同类错误是否重复发生？

因此需要将用户反馈转化为可执行的正确契约，并用回归测试控制修复发布。

## 2. 产品目标

### 2.1 用户目标

- 业务用户可以低成本提交错误结果；
- 工作人员能够查看错误发生时的完整上下文；
- 工作人员可以定义正确行为；
- 可治理语义问题无需修改代码即可修复；
- 发布前能够验证当前问题和受影响问题；
- 修复结果可以追溯到具体指标版本。

### 2.2 业务结果

- 提高 Bad Case 可归因率；
- 缩短平均关闭时间；
- 提高一次验证通过率；
- 降低修复后复发率；
- 防止错误修复绕过发布门禁。

### 2.3 本期不处理

本功能不直接修改：

- 指标公式；
- 指标单位；
- 模型粒度；
- 默认时间字段；
- Join、基数或 Fanout；
- Schema；
- 权限策略。

上述问题必须进入对应治理模块。

## 3. Bad Case 定义

Bad Case 是指：

> 在明确的业务语义、权限和预期契约下，系统实际行为与正确行为不一致，或者过程存在不可接受风险的请求。

Bad Case 必须包含：

1. 输入上下文；
2. 系统实际行为；
3. 人工确认的正确契约。

### 3.1 分类

| 分类 | 示例 |
| --- | --- |
| `METRIC_WRONG` | 退款后净收入被识别为支付实收金额 |
| `QUERY_SHAPE_WRONG` | 指标正确，但时间、维度、过滤或排序错误 |
| `DATA_WRONG` | Join、聚合或执行结果错误 |
| `INTERPRETATION_UNTRUSTED` | 结果正确，但解读缺少证据或产生因果幻觉 |
| `CHART_WRONG` | 图表类型不符合分析意图 |
| `PERMISSION_ISSUE` | 越权查询或权限阻断错误 |
| `SCHEMA_ISSUE` | 结构变化未正确传播或错误阻断 |
| `UI_ISSUE` | 关键信息缺失或交互阻碍完成任务 |
| `OTHER` | 无法归入现有分类 |

## 4. 用户故事

### 业务分析用户

> 当系统返回不符合预期的结果时，我希望能够描述问题和期望表现，以便数据团队进行修复。

### 指标产品经理

> 当我收到 Bad Case 时，我希望看到当时的指标、DSL、血缘、结果和系统状态，从而判断错误发生在哪一层。

> 当问题属于指标语义时，我希望直接修改名称、定义、别名或正反例，并在发布前验证修复。

> 当我发布修复时，我希望系统自动回归关联 Golden，避免修好一个问题却破坏其他问题。

### 平台管理员

> 当 Bad Case 涉及权限、Join 或 Schema 时，我希望它被路由到对应治理模块，而不是通过关键词配置掩盖。

## 5. 核心流程

```text
业务用户提交反馈
→ 反馈进入待确认队列
→ 工作人员查看完整执行现场
→ 确认是否为 Bad Case
→ 选择正确指标和正确终态
→ 建立 Golden 契约
→ 归因到语义或结构治理
→ 修改对应资产
→ 验证当前 Bad Case
→ 回归同指标 Active Golden
→ PASS 后发布不可变新版本
→ 记录关闭时间与修复效果
```

## 6. 状态机

| 状态 | 含义 | 允许操作 |
| --- | --- | --- |
| `SUBMITTED` | 用户已提交反馈 | 查看、确认、驳回 |
| `CONFIRMED` | 工作人员确认为 Bad Case | 定义 Golden、归因 |
| `IN_REMEDIATION` | 正在修改相关资产 | 保存草稿、运行验证 |
| `VALIDATED` | 当前问题和关联回归通过 | 发布 |
| `PUBLISHED` | 修复版本已发布 | 关闭、观察复发 |
| `REJECTED` | 反馈不是有效 Bad Case | 记录原因 |
| `BLOCKED` | 需要结构或权限治理 | 跳转对应模块 |
| `CLOSED` | 闭环完成 | 查看历史 |

状态规则：

- 草稿内容变化后，`VALIDATED` 自动失效；
- 没有人工 Golden 契约不能进入验证；
- 回归失败不能发布；
- 结构和权限问题不能在本功能内发布；
- 发布产生不可变指标版本。

## 7. 功能需求

### 7.1 用户提交反馈

输入：

- 反馈类型；
- 严重程度；
- 问题描述；
- 期望表现。

系统自动关联：

- Query ID；
- 会话；
- 当前用户匿名标识；
- 业务域；
- 指标及版本；
- DSL；
- 执行结果摘要；
- Evidence；
- Reflection；
- 当前权限范围；
- Schema 状态。

### 7.2 Bad Case 工作台

支持：

- 按状态、类型、严重度、指标和时间筛选；
- 查看原始问题和当前终态；
- 查看候选指标及分数；
- 查看指标版本、DSL、血缘和结果摘要；
- 查看执行步骤；
- 确认或驳回反馈；
- 指定主要根因阶段；
- 跳转到指标、Join、Schema 或权限治理。

### 7.3 Golden 契约

工作人员确认：

- 预期终态；
- 正确指标；
- 正确意图；
- 正确时间范围；
- 正确维度；
- 正确过滤；
- 正确排序和限制；
- 预期图表；
- 预期 Reflection 状态；
- 预期行数；
- Oracle 或结果允许误差；
- 说明。

约束：

- 原错误指标不能自动成为正确指标；
- 原 DSL 不能自动成为 Golden；
- Golden 必须由工作人员主动确认；
- Golden 与反馈、业务域和指标版本建立关联。

### 7.4 语义修复

允许修改：

- 指标名称；
- 业务定义；
- 别名；
- 正向问法；
- 反向问法；
- Owner；
- 其他不改变计算结果的描述。

系统检查：

- 别名冲突；
- 正反例重复；
- 与其他指标的语义边界；
- 必填字段；
- 草稿指纹。

### 7.5 验证与回归

运行范围：

1. 当前 Bad Case；
2. 同指标 Active Golden；
3. 语义冲突指标关联 Golden；
4. 必要的安全门禁用例。

验证项：

- 终态；
- 指标；
- DSL；
- 时间；
- 维度；
- 过滤；
- 图表；
- 行数；
- Oracle；
- Reflection；
- 权限；
- 危险执行。

### 7.6 发布

发布前置条件：

- Golden 已确认；
- 当前草稿与验证草稿指纹一致；
- 当前 Bad Case PASS；
- 受影响 Golden 全部 PASS；
- 无结构治理阻断；
- 发布者拥有权限。

发布结果：

- 生成不可变指标新版本；
- 旧版本保留；
- 保存发布人与时间；
- 绑定 feedback_id 和 golden_id；
- 重建受影响语义索引；
- 记录产品事件。

## 8. Bad Case 归因规则

原则：

> 以最早偏离正确契约的节点作为主要根因。

| 现象 | 主要根因 |
| --- | --- |
| 正确指标未进入候选 | 语义资产或召回 |
| 正确指标进入候选但选错 | 候选裁决 |
| 应澄清却直接回答 | 阈值或澄清策略 |
| 指标正确但时间错误 | 时间解析 |
| 指标正确但维度/过滤错误 | Query Understanding |
| DSL 正确但 SQL 错误 | 编译器 |
| SQL 正确但数据错误 | 数据源或执行 |
| 结果正确但结论错误 | Interpretation |
| 无证据结论被放行 | Reflection |
| 无权限但执行 | 权限门禁 |
| Schema 变化后仍执行 | Schema 影响传播 |

## 9. 权限

| 角色 | 权限 |
| --- | --- |
| 业务用户 | 提交反馈、查看自己的反馈状态 |
| 指标产品经理 | 确认、建立 Golden、修改语义、验证、发布 |
| 平台管理员 | 处理权限、Schema 和系统问题 |
| 只读审核员 | 查看 Bad Case、Golden 和发布历史 |

## 10. 埋点

| 事件 | 触发点 | 关键属性 |
| --- | --- | --- |
| `feedback_submitted` | 用户提交反馈 | 类型、严重度、业务域、指标 |
| `badcase_confirmed` | 工作人员确认 | 根因阶段、负责人 |
| `golden_created` | 建立正确契约 | 指标、预期状态 |
| `remediation_saved` | 保存修复草稿 | 修改字段、草稿指纹 |
| `badcase_closure_validated` | 运行验证 | PASS/FAIL、回归数量、耗时 |
| `metric_version_published` | 发布修复 | 新版本、feedback_id、golden_id |
| `badcase_closed` | 闭环完成 | 总关闭时长、验证次数 |
| `badcase_recurred` | 同类问题复发 | 原反馈、复发版本 |

## 11. 成功指标

### 核心指标

- Bad Case 平均关闭时间；
- 一次验证通过率；
- 发布后复发率；
- 可归因率；
- 语义问题自助关闭率；
- 受影响 Golden 回归覆盖率。

### 安全门禁

- 未验证发布次数为 0；
- 权限问题被语义修复绕过次数为 0；
- 结构问题被别名配置掩盖次数为 0；
- 危险执行次数为 0。

## 12. 验收标准

1. 用户可以从查询结果提交反馈；
2. 反馈自动关联完整执行现场；
3. 工作人员可以确认正确指标和预期终态；
4. 可以建立 Golden 契约；
5. 可以修改指标语义草稿；
6. 草稿变化会使旧验证失效；
7. 当前 Bad Case 和同指标 Golden 可以自动回归；
8. 任一回归失败时禁止发布；
9. 结构与权限问题必须路由到对应治理模块；
10. 发布生成不可变指标新版本；
11. 发布记录可追溯到反馈和 Golden；
12. 所有关键操作产生产品事件。
